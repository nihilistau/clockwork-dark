An apply never changes a running story in place. The supervisor first checks that a new server answers (unless "apply anyway" is ticked), then pauses every story's new turns and waits for the running ones to finish (if they outlast the drain time, nothing is changed), then writes its admin layer and restarts each story's worker in turn, one story at a time; a turn queued but not started is answered busy. Players must reload their page once their story is back: the game's page does not reconnect on its own after a server restart until the v0.21.0 client. If a worker will not start under the new settings, the previous settings are restored and the workers restarted again. A model server that is down after the apply is not rolled back: watch the health row above. A key set in the operator's configuration file is locked here: change it there.
