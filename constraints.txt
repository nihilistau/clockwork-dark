# constraints.txt -- the versions the suite was proven green on.

# requirements.txt says what the code supports (">=" ranges); this file says
# what was tested. Every installer uses both:
#
#     pip install -r requirements.txt -c constraints.txt
#
# (scripts/start.ps1, scripts/start.sh, the Linux container run in
# docs/HOSTING.md, CI and the Dockerfile). A constraint installs nothing: pip
# ignores a pin on a package nothing requires, so the Windows-only rows below
# (pywin32, pywin32-ctypes, colorama) cost a Linux install nothing.
#
# WHERE AND WHEN. Taken on 2026-09-30 (v0.20.0 T4) from the owner's Windows
# .venv (Python 3.11.9) with `pip freeze --all --exclude-editable`, before the
# Linux container run. Three rows were left out, on purpose:
#
#   pip and setuptools -- installer tooling is not pinned (v0.20.0 T4 fix
#   round 1). Nothing the game requires needs them, so a pin only ever
#   reached an isolated build (PIP_CONSTRAINT) and forced the .venv's old
#   setuptools 65.5.0, a version with published advisories, onto it. Each
#   environment keeps its own (the Linux container ran pip 24.0 and
#   setuptools 79.0.1, the image's).
#
#   fastmcp-slim==3.4.7 -- a stale record. The .venv holds fastmcp 3.2.4's
#   files (every file in its RECORD hashes true) beside the dist-info of an
#   earlier fastmcp 3.4.7 / fastmcp-slim 3.4.7 install that 3.2.4 overwrote.
#   `import fastmcp` and importlib.metadata both answer 3.2.4, the version
#   requirements.txt names, and nothing under 3.2.4 requires fastmcp-slim.
#
# WHY. The goldens pin bytes, and engineio's CORS defaults, Werkzeug's
# test-client routing and the save-id probe are all version-dependent: the
# platform the suite proves green is the platform that ships only if it is
# the same versions (spec §3.10). tests/test_constraints.py holds every
# requirement to a pin, and the installed version to it.
#
# RE-PINNING is a deliberate edit, recorded in CHANGELOG.md, never a side
# effect of an install.
#
# ONE ROW FROM ELSEWHERE: gunicorn==23.0.0 (v0.20.0 T13) is a server-only
# requirement (requirements-server.txt) that does not run on Windows and is
# not installed in the owner's .venv, so it was pinned from the version
# installed and proven in the Linux container run (docs/HOSTING.md § Linux),
# not from the .venv's freeze. Its one dependency, packaging, is pinned above.
