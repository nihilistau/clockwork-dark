# v0.20.0 — Linux and hosting — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Linux becomes a first-class platform, and a hosted mode lets a small group play the operator's stories in a browser against one shared model server, run by a supervisor behind one front door, with an admin panel for the operator. All of it is opt-in, and none of it changes the game a local player gets.

- Linux: the suite is green in a Linux container on this workstation (and in GitHub Actions once pushed); every script has a POSIX way in; no code assumes a separator, a drive letter, a case-insensitive filesystem or an `.exe`; one set of dependency versions everywhere; vLLM verified live, or recorded as not runnable on the RTX 2060.
- Hosted mode (`hosting.enabled`, default **false**): operator-made accounts, a signed-cookie login, one gate for every HTTP route and one wrapper for every socket event, ownership at every door that names a session or a save, per-account saves, a FIFO queue on the shared model server with admission before a turn touches state, rate limits and input caps, gunicorn with one threaded worker per process, and a Docker image with a compose file.
- Orchestration and the admin panel (owner scope, 2026-09-30 13:10; spec §14): a supervisor runs one worker process per story in `hosting.stories` and holds the model server's lanes for all of them over a loopback bus; a front door logs a player in once and routes them to the story they pick (HTTP proxied, Socket.IO polling proxied, WebSockets relayed message by message); admin accounts get a server-rendered `/admin` panel for accounts, live sessions, saves (metadata), stories, the model server and its queue (the `llm.*` settings players cannot change, applied by a drained restart), and metrics and errors, **metadata only**; every admin action is audited.
- Local mode: byte-identical to v0.19.0 bar exactly two sanctioned differences (the loopback bind the owner chose, and `paths.saves` leaving the games payloads), plus the survey's defect fixes, which touch no recorded byte. It never imports `engine.hosting` and never starts the supervisor.

**Architecture:**
- A local-mode golden, recorded on untouched v0.19.0 code in Task 1, is the first invariant. v0.19.0's LM Studio golden runs beside it, unchanged.
- The survey's defects (save ids as paths, cwd-relative outputs, the secrets chain's scopes, the unguarded `join_session`, the LAN bind) are fixed in all modes, each with a failing-first test.
- One storage root (`storage.root`, `CLOCKWORK_DATA_DIR`) owns every runtime output; saves leave story manifests.
- Thread safety comes before hosting: every module-level singleton is classified from a mechanical scan and pinned by a test, the races are fixed, and hosted mode warms every cache before it serves.
- `engine/hosting/` is imported only in `FlaskScene.__init__`'s hosted branch (and by `wsgi.py`), so local mode never loads it. HTTP is gated by one `before_request`; Socket.IO by one wrapper, `FlaskScene.on`, whose coverage a test enumerates. The owner rides a `ContextVar` in `engine/session/store.py`, which every `require` reads.
- The gate becomes a FIFO queue in hosted mode, and a turn is admitted to the narration lane before any mechanic runs.
- A hosted instance is three kinds of process (spec §14.1): a **supervisor** (plain Python, no HTTP: children, health and restarts, logs, the shared lanes, the metrics store, the admin layer), **workers** (Tasks 7–9's hosted app, one story each, on OS-picked loopback ports) and a **front door** (login, the story picker, the `/admin` panel, and the proxy to the chosen worker). They talk over a **bus**: one loopback TCP connection per child, a single-use token per child start in that child's environment only, newline JSON, a closed op table with the roles allowed to call each op, and a lifeline (a child exits when its connection closes, and the supervisor frees what it held). The gate gains a lane-backend seam so the supervisor's lanes plug in without `engine/llm/gate.py` importing `engine.hosting`.
- The front door is the session cookie's one writer; workers only read it. Its WebSocket door is a message relay built on `simple-websocket`, proved under gunicorn in the Linux container in Task 13, before the admin panel is built on the front door.
- Admin state never leaves metadata: a closed metrics schema (SQLite, the supervisor its one writer), an allowlisted save projection, a projection of the Oracle's numbers, and a sentinel test over every admin surface. Model settings are edited in a hosting-owned config layer (`<storage.root>/hosting/admin.yaml`, read whenever hosting is on) and applied by a drained restart, one worker at a time, never by a cache reset under live turns.

**Tech Stack:** Python 3.11, Flask 3.1 + Flask-SocketIO 5.6 (threading mode), Werkzeug (`security`, `ProxyFix`), pytest, httpx (every mocked model call through `tests/llm_wire.py`; also the front door's proxy), PyYAML, `sqlite3` and `selectors` (standard library), `simple-websocket` (already installed as python-engineio's dependency: the front door's WebSocket relay, both ends, and the tests' client); gunicorn (optional `server` extra, POSIX only); Docker and Docker Compose; GitHub Actions; `vllm/vllm-openai` (live only, with consent). No new runtime dependency for the panel, the bus or the front door.

**Spec:** `docs/superpowers/specs/2026-09-30-linux-and-hosting-design.md`. The spec's § numbers are cited per task. Its "Findings the survey turned up" 1–15 are each fixed or recorded by a named task below. The design review (`.superpowers/sdd/2026-09-30-v0.20.0-linux-and-hosting/v020-design-review.md`, 28 findings) and the review of §14 (`.superpowers/sdd/2026-09-30-v0.20.0-linux-and-hosting/admin-design-review.md`: C1–C4, I1–I11, Minors 1–13) are folded into the spec in place, and the owner's decisions (`.superpowers/sdd/2026-09-30-v0.20.0-linux-and-hosting/v020-owner-decisions.md`) land in Task 2 (the local bind becomes `127.0.0.1`) and Tasks 10–17 (the admin panel and orchestration, spec §14).
