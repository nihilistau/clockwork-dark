**Verdict: approved with fixes.** The shape is right. Item 1 narrows a negation to its clause and never widens a
window. Item 2 ranks only over the cap, so every list that fits is byte-identical. Item 4 forks with
`from_dict(to_save_dict())` and named streams, and bounds its cost by a step count. Item 5 branches only from real
states, and item 6 adds no judgement. Rule 12 and the canon are respected.

But three findings are Critical, because each makes a Goal false as written:
- C1: the "pre-turn snapshot" the echoes and checkpoints reuse is taken after the intent has run;
- C2: xdist reorders work units by size, so "heavy first" never reaches the scheduler;
- C3: a save with a `checkpoints/` folder cannot be deleted.

None needs a redesign. Fix C1-C3 and the Important findings in the spec before T1, and have them re-checked.

## Critical

**C1. No pre-turn snapshot exists. The one §5.4 and §6.3 reuse is taken after the intent has run (§5.4 step 3,
§6.3, §6.4, Goal 4, Goal 5).**
- **Evidence:**
  - `default_state.run_turn` does things in this order:
    - `_background_tick` (`:1232`), gossip into the ledger, `execute_intent` (`:1298`);
    - `authored_choice.resolve`, `law.patrol`, `director.ensure_scene` (`:1356`);
    - the negotiation pipeline (its own `StateTransaction`, `pipeline.py:268`);
    - only then `storyteller.run_turn`.
  - The storyteller's `StateTransaction(self.engine.state)` (`storyteller.py:989`) is taken after all of that. Its
    own comment says the resolved intent is "Already applied to the world before this method was entered"
    (`:949-953`).
  - So "the `StateTransaction` snapshot dict the turn already took" (§5.4) holds the TAKEN road. Fork B would apply
    the alternative on top of it.
  - §6.3's checkpoint ("costs only gzip") is not the pre-turn state either. A branch from it would replay a turn
    whose intent, deal and NPC commits have already landed.
  - The snapshot is also private (`_snapshot`) and lives inside the storyteller, out of `run_turn`'s reach.
- **Fix:**
  - Name a new capture point. In `run_turn`, take `pre_turn = state.to_save_dict()` after `_background_tick` and
    gossip, and before `execute_intent`.
  - Take it only when someone needs it: the story is opted in to echoes (§5.6), or `replay.journal.enabled` is on
    and the turn is a checkpoint turn under §6.3's thinning.
  - Pass it to the echo pass and to `_autosave`.
  - Restate the cost as one extra serialisation plus gzip. At READ RECEIPTS' day 60, `to_save_dict` alone is
    13 ms (CLAUDE.md, the whole-state serialisation row).
  - T8 must also measure it against `tests/test_social_turn_cost.py`'s `MEDIAN_BOUND_MS` (400 ms), which every
    world turn now pays.
  - State that the snapshot is post-tick. A branch therefore replays from the world as the player chose in it,
    with that turn's wall-clock tick already in it.

**C2. xdist reorders work units by size, so item 3A's "heavy first" never reaches the scheduler (§1.3, §10.1,
Goal 3).**
- **Evidence:**
  - `LoadScopeScheduling.schedule` (xdist 3.8.0, `scheduler/loadscope.py:368-382`) builds the work queue sorted by
    the number of tests in each scope, descending, whenever `loadscopereorder` is set.
  - `loadscopereorder` defaults to True (`plugin.py:131-142`), and `run_tests.py` does not pass
    `--no-loadscope-reorder`.
  - Each `test_social_save_size.py` param is a scope of one test. Its fixture `receipts_active` is
    function-scoped, so no `xdist_group` is formed.
  - So every multi-test group is handed out before any heavy single test, whatever order
    `pytest_collection_modifyitems` leaves.
  - The research's "popped in collection order" (`research-item-3.md:27`) missed the sort.
  - Even with the sort off, the initial loop assigns one unit per node and then calls `_reschedule` once per node
    (`:396-402`). That gives units 7-12 to gw0-gw5 in node order. With the sixteen heavy units §10.1 names, gw0
    holds H1 and H7 from the start: the heaviest pair, which cannot be stolen. "So no worker holds two
    multi-minute tests" (research, `:112`) is false.
  - §10.1's guard tests only the collection order, so it would pass while the run stays bound by one worker.
- **Fix:**
  - Implement `pytest_xdist_make_scheduler` (an xdist hook, `newhooks.py:96`) in `tests/tier_plugin.py`. Return a
    `LoadGroupScheduling` subclass that:
    - orders the queue by heavy weight (descending), then by today's size order;
    - deals heavy units longest-first to the least-loaded node;
    - prefetches nothing behind a heavy unit until every node holds one.
  - Or pass `--no-loadscope-reorder` and deal the heavy units in snake order (gw0..gw5, then gw5..gw0). State the
    cost of losing the size sort for the rest of the run.
  - Replace the collection-order guard with a scheduler test: fake nodes, a synthetic collection, and an assertion
    that the first W heavy units land on W nodes and the heaviest two never share one.

**C3. A save with a `checkpoints/` folder cannot be deleted, and §6.3 says the opposite (§6.3 "already the case",
§13 R9).**
- **Evidence:**
  - `SaveStore.delete` (`saves.py:895-903`) runs `child.unlink(missing_ok=True)` for each `directory.iterdir()`
    child, then `directory.rmdir()`.
  - `unlink` on a directory raises (`PermissionError` on Windows, `IsADirectoryError` on POSIX). So the first
    delete of a checkpointed save raises, and the folder and its index row survive.
  - Any other folder walker that assumes flat files breaks the same way: index eviction, the hosted purge and the
    admin Saves tab. T8 must list them.
- **Fix:**
  - Write the checkpoints as flat files (`checkpoint-<turn>.json.gz` beside `save.json`), which keeps `delete`
    unchanged.
  - Or make `delete` remove `checkpoints/` by its exact computed path, one file at a time and then the empty
    folder (no indirect `rmtree`, AGENTS.md and the owner's no-indirect-rm rule). Add a test that deletes a save
    holding checkpoints, on both platforms' error types.
  - State whether checkpoints, not only the journal, are forced off in hosted mode. Today §6.2 rules the journal
    and §6.3 is silent.

## Important

**I1. The echo pass runs after the epilogue is built and before `turn_update` is sent. A door's own echo therefore
misses its epilogue, and every pivotal turn's choices arrive late (§5.5 "When it runs", §5.4 rule 2).**
- **Evidence:**
  - `ending = epilogue_module.for_state(state)` is computed at `default_state.py:1613`.
  - `_autosave` runs at `:1660`, and `emit_callback("turn_update", ...)` only after it (`:1680`).
  - "After the narration has been emitted and before its autosave" therefore puts 0.15-0.75 s between the streamed
    prose and the choices. The player waits, rather than reading while it runs.
  - Rule (b) makes door beats pivotal. On the turn a door locks, the epilogue has already been rendered without
    that turn's echo, and the run is over, so no later turn renders it.
  - "The first candidate of the day wins" lets a morning thread strike (rule c) pre-empt the evening's door.
- **Fix:**
  - Run the echo pass before the payload is built, after `_evaluate_quests` (`:1528`), and say that the choices
    wait for it.
  - Or run it after the emit, and re-render the epilogue when it lands. That needs a second emit or a
    `last_turn` refresh.
  - Rank candidates within a day (a over b over c, door beats always computed) instead of first-come.
  - Persist the day consumed, so a resume cannot re-open the day (I3).

**I2. The echo's words carry model text, against "No model writes or sees them" (§5.4 "Labels are the offered
choices' own labels", §5.6, §5.7).**
- **Evidence:**
  - The offered choices are the narrator's (`merge_choices(agreed, storyteller_result.choices)`,
    `default_state.py:1541`), and their labels are model-written.
  - `{not_taken}` in the authored template is filled from them, so a model sentence reaches the epilogue and the
    save.
  - §5.7's test (StubNarrator versus a raising narrator, "equal") cannot show otherwise. The two offer different
    choices, so their echoes differ anyway, or the test compares nothing.
- **Fix:**
  - Store and render `intents.player_label(state, action, target)` (`intents.py:1060`), the engine's own label for
    the pair, read on the pre-turn fork. Keep the offered label only in the journal (local).
  - Replace the test: a narrator whose choice labels carry a sentinel, and an assertion that the sentinel reaches
    neither `state.echoes` nor the rendered `counterfactuals`.

**I3. `state.echoes` has no single writer, and its name collides with the epilogue's own `echoes` (§5.4 step 4,
§9.1; rule 3).**
- **Evidence:**
  - Rule 3: `effects.apply_effect` is the only writer of game state. The spec writes `state.echoes` directly.
  - `Epilogue` already has `echoes: [{speaker, text}]`, the authored closing lines (`epilogue.py:80, 96`;
    `DEFAULT_ORDER` includes `"echoes"`; `Ending.jsx:59-71` draws them).
  - "Echo" now names two unrelated things, in the same payload object (`ending`), the journal and AUTHORING.
- **Fix:**
  - Add an effect type (`counterfactual`, ops `keep`/`mark_day`) through `apply_effect`. Include the
    "last candidate day" the bound needs (I1).
  - Rename the field and section `counterfactuals` everywhere: the state field, the payload key and the journal's
    `echo` column.
  - Add the field to `tests/test_state.py`'s non-default round-trip and to docs/STATE.md.

**I4. A fork's projected week is thinner than a real one, so most §5.3 signals can move only through the one
applied intent (§5.1 `step`, §5.3).**
- **Evidence:**
  - `advance_time` runs these: doom, beats, clocks, survival, `npc_sim`, agendas, law, jobs, the social pass, the
    death check, declared events and thread expiry (`clock.py:166-360`).
  - Not run: quest evaluation (`_evaluate_quests`, in `run_turn` only), deck dealing (`director.ensure_scene`), the
    patrol, `authored_choice.resolve` or the pipeline.
  - So a `forces_scene` beat or clock is never dealt in the fork, no stage completes, and `ending_closer` moves
    only when the intent itself or a time-driven value moves a score.
  - §5.3 reads "`endings.recompute` scores". `recompute` writes two tracks through `apply_effect`
    (`endings.py:624-636`), and `_score` can read the ledger (`:409`), which a fork does not have.
- **Fix:**
  - Define `step` as `advance_time` plus, once per in-game day, `QuestEngine.evaluate(fork, ledger=None)` and
    `director.ensure_scene(fork)` with the first offered beat taken. Or state plainly that quests and decks are not
    projected, and drop the signals that need them.
  - Read `endings.eligible` (read-only), not `recompute`, and refuse an opt-in whose ending `score:` reads the
    ledger.
  - Run `fork A` through the same post-intent sequence the live turn runs (authored, patrol), or say it is the
    intent alone.
  - Add a NOT WIRED row for whatever is not projected.

**I5. A branch from a checkpoint loses or misdates the ledger, and READ RECEIPTS' sidecars (§6.3, §6.4).**
- **Evidence:**
  - A save is `save.json` plus `memory.json` (the ledger: relations, facts, turn buffer and summaries; it is in
    the local-mode save tree). READ RECEIPTS adds `phone_archive.jsonl` and the phone media folder.
  - A checkpoint holds only the state. "Copy the checkpoint into a new save folder" leaves the branch with no
    memory, or with today's memory, which knows about turns that the branch has not played.
  - READ RECEIPTS' state references archived thread history that the archive keeps by spill offset.
- **Fix:**
  - Checkpoint `session.ledger.to_dict()` beside the state (one gzip holding both), and write the branch through
    `SaveStore.save(state, memory=...)`.
  - For phone stories, record the archive's byte length in the checkpoint and copy that prefix. Or refuse a
    READ RECEIPTS branch with a reason and add a NOT WIRED row.
  - Say whether the branch copies `transcript.jsonl` and `turns.jsonl` up to turn n, so its timeline shows its
    history.

**I7. Site D's new "`my` followed by more words" rule reaches `plan_claimed` and the arrival check as well, and it
