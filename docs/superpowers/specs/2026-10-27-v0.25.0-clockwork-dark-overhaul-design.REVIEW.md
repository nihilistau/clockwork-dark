# Review: v0.25.0 Clockwork Dark overhaul design (2026-10-27-v0.25.0-clockwork-dark-overhaul-design.md)

Reviewer: opus spec review, design only. Nothing was edited except this file, and no engine code was run.
Inputs:
- the spec at e0cab2b;
- AGENTS.md, CLAUDE.md, the HUE & CRY model spec and the v0.24.0 review's format;
- the flagship as it stands (`games/clockwork-dark/`, `ui/src/stories/clockwork-dark/`);
- the engine code each claim names.

The owner's rulings are taken as given: 47 xai plates, the run-length bands as written, and live play gated on
the owner. Nothing below reopens them.

**Verdict: approved with fixes.** The shape is right: doors as dealt cards, gated on their own ending, with a
fixed lever order and no constant moved before T10. Rule 12 and the canon ids are respected. But four findings are
Critical, because each makes a stated Goal or Acceptance item false as written:
- C1: menu beats cannot be hidden per beat;
- C2: the overlay path dies in `execute_intent`;
- C3: the converted events reuse streams the wall-clock tick still advances;
- C4: two endings still need the narrator.

None needs a redesign. Each needs a paragraph, a table row or one named engine seam. Fix C1-C4 and the Important
findings in the spec before T1, and have them re-checked.

## Critical

**C1. Menu beats cannot be offered conditionally. `S1`, `S2` and `H1` depend on a per-beat `when:` the engine
drops (§4.3, §4.2, §6.6).**
- **Evidence:**
  - `deck.bound_beats` (`engine/content/deck.py:205-273`) keeps only `id`, `text`, `label`, `gate` and `band`.
    A beat's `when:` is silently discarded.
  - `director.options` and `player_options` (`engine/content/director.py:136-224`) offer every beat of a menu
    card.
  - So `S1`'s "one beat per carried candidate, each `when: has_item`" offers all three. So does `S2`'s
    pay-the-name/pin/shard.
  - `H1`'s "`stay` when eligible / `stay_anyway` when NOT eligible" offers both, every time. A player whose
    Hearth is open can therefore take the fail-forward, and one whose Hearth is shut sees `stay`. `stay` then
    refuses its own lock.
  - §6.6 claims this is all existing data use.
- **Fix:** pick one route and write it into §4.3.
  - **Data route.** Split `H1` into two cards with card-level `when:` (`H1a_stay`: eligible `the_hearth_holds`;
    `H1b_stay_anyway`: not eligible), each with its own ENDING_DOORS row. Make `S1` and `S2` one card per item
    (`S2_pay_the_pin` and so on), each gated by a card `when:`.
  - **Engine route (E6).** Teach `bound_beats` to keep a beat `when:`, and teach `options`, `player_options` and
    the card verb's enum to filter on it. This is byte-identical for every other story: no shipped beat carries
    `when` today (all `games/*/data/scenes/*.yaml` were scanned).

**C2. The overlay path is refused by `execute_intent`. "Unchanged code" is false (§7.1, §7.2, §6.2).**
- **Evidence:**
  - `engine/agents/tool_dispatcher.py:150-171` re-checks every intent against `legal_intents(engine.state)`.
    That list never holds `use`, `equip` or `unequip` (§7.2's own design), and it caps `buy`, `sell`, `eat`,
    `work` and `craft` at eight targets (`intents.py:80`, `_eat:243`, `_buy:298`, `_sell:731-735`, `_work:446`,
    `_craft:492`).
  - So every overlay-only press is refused ("use is not something you can do here right now"). So is any ninth
    target.
  - §12.3's "a ninth sellable thing is legal from the overlay" fails.
  - `describe_intent` (`intents.py:1023-1045`) reads the same list. §7.1's `sentence = describe_intent(intent)`
    is therefore `""` for exactly these intents.
  - `legal_intents` also returns only the card or encounter verb while a scene owns the turn (`intents.py:863-918`).
    `overlay_targets` has no such guard in the spec, so a pack press during a dealt door card would run past it.
- **Fix:** name the dispatcher as part of E2.
  - `run_guarded` → `run_turn` → `execute_intent` carries an `overlay=True` mark.
  - With the mark, legality is checked against `overlay_targets(state)` under the turn lock.
  - `overlay_targets` returns nothing while `intents.scene_owns_turn(state)`.
  - `describe_intent` gets an overlay twin, or takes the label from `overlay_targets`.
  - Add the scene-owns-turn refusal to `tests/test_overlay_intents.py`.

**C3. E1's "keep the stream names" makes the converted events depend on wall-clock ticks (§6.1, Goal 3,
Acceptance).**
- **Evidence:**
  - `WorldSim.on_tick` (`engine/world/world_sim.py:250-272`) passes `rng or world_rng(state, SCHEDULE_CARAVAN)`,
    and the same for TINKER and MILITIA. The draw is made eagerly on every background tick, before
    `check_caravan` looks for a config block.
  - `world_rng` increments the stream's counter on each call (`engine/game/rng.py:120-132`).
  - So after the flagship drops its top-level blocks, its `schedule.caravan`, `schedule.tinker` and
    `schedule.militia` counters still advance once per wall-clock tick (`default_state.py:1180-1190`).
  - E1's `stream: schedule.caravan` would then draw at a counter set by how often real time ticked. That is R-03
    again, and Goal 3 is lost.
  - §12.3's cut test drives `advance_time` alone, so it would pass while play diverges.
- **Fix:**
  - Give the declared events new streams (`schedule.caravan.day`, and so on) and drop the "counters continue"
    rationale. A v0.24.0 save gains fresh streams, which is harmless.
  - Leave `on_tick` untouched. Its eager draws are pinned by the other stories' save digests (§11.3).
  - Extend the cut test to run through `WorldSim.on_tick` with differing tick counts.

**C4. Two endings still depend on the narrator. Goal 1 and the "card-only critical paths" acceptance fail (§4.3,
§12.2).**
- **The Counted March.** `served` needs a march quest completed or `stood_the_wall`, and no card-only route reaches
  either:
  - Every march quest's first stage completes only on a narrative flag: `militia_press.watch_it_happen`
    `nf_press_watched`, `toll_roads.meet_the_chain`, `refugees.hear_them`, `burned_farmstead.walk_the_ground`,
    `conscription_list.get_near_it`.
  - `seras_compromise` cannot start until `conscription_list`, `burned_farmstead` or `refugees` is complete.
  - `seras_bargain` needs `conscription_list` active, which needs `militia_press` or `toll_roads` complete.
  - None of these stages is carried by a §4.3 card. `the_press` sets reputations and `hid_the_boy`, not the
    quest's flags.
- **The Pin and the Join.** `the_ninth_pin.pay_for_it` keeps `disposition: {npc: npc_ilya, min: 20}`, which §4.3
  keeps deliberately. Disposition is written only by the model's `npc_disposition` patch
  (`engine/memory/ledger.py:663-671`, the sole caller of `adjust_disposition`), and no effect type writes it.
  The scripted run with `set_narrative_flag` patched out can never pass that stage.
- **Fix:**
  - Add march cards: fold `militia_press`'s `watch_it_happen` and `the_weller_boy` flags into `the_press`, or into
    a `the_gate` deck at Sera's hours, plus `conscription_list`'s three stages.
  - Replace the disposition clause with something the engine writes, such as
    `reputation: {faction: tinkers, min: N}`. Or add a bounded `disposition` effect as a named engine seam.
  - Re-derive every ending's critical path in §4.3 as a table (stage → what completes it) so the acceptance test
    has a script.

## Important

**I1. Keeping the narrative flags on the two fixed stages reopens bugs 1 and 2 through the narrator, and strands
the Price's door (§4.3 "whichever comes first wins", §11.1).**
- **Evidence:**
  - Once `take_it_or_dont` loses its stage `item` effect, a narrator-raised `nf_ninth_taken` completes it with no
    pin. `pin_held` can then never hold.
  - A narrator-raised `nf_sacrifice_chosen` sets no `sacrifice_offered_<item>`, so `S2` has nothing to pay.
  - A narrator-raised `nf_sacrifice_paid` completes `pay_it` (its `not_has_item` check is removed) with nothing
    removed, and the quest completes.
  - Once the quest completes, `the_price`'s deck `when:` (stage at `pay_it`) is false. The Price Asked is then
    eligible but has no door.
  - A v0.24.0 save already at `pay_it` falls into the same hole. §12.4's fixture stops at `choose_what`.
- **Fix:**
  - Drop those narrative flags from the stages whose effects moved onto beats. The cards write them, so
    `test_every_narrative_flag_is_reachable_from_some_stage` still holds.
  - Or key the door deck on `{ending: {eligible: the_price_asked}}` rather than on the stage.
  - Add a `pay_it` save fixture.

**I2. A door's person is not where the door deck's hours say (§4.3, §12.2 "dealt only where its person is",
R4).**
- **Evidence:** `npc_sim.resolve_npc` (`engine/world/npc_sim.py:317-358`) ranks a quest pin over an event, and an
  event over a routine or an override, for every hour of the event:
  - `tinker_camp` (`npc_ids: [npc_ilya]`, 3 days) holds Ilya at `tinker_caravan` all day, after his 0.50 move too.
  - `the_ninth_pin`'s `on_start` pins Ilya home for the whole quest. That overlaps `the_sacrifice`, since both
    open on `naming_the_wound`.
  - `militia_press` puts Sera in the square for its whole day.
- **Consequences:**
  - `the_price` and `the_muster_roll` deal their doors with the person elsewhere, and the presence test fails over
    seeds.
  - Edrin's "Millhaven market on days the caravan is in" (§3.3) cannot be expressed. Routines carry no condition,
    and an event's `npc_ids` go to the event's own `location_id` (the square).
- **Fix:**
  - Add a small generic predicate, `npc_here: <id>` (present via `npc_sim`, awake). Make it a named seam, and
    have every door deck's `when` read it.
  - Or write each window with `none: [{event_active: ...}]` and pin clauses.
  - Drop Edrin's market clause.

**I3. E1 is not cut-invariant inside one long advance (§6.1, §12.3, Acceptance "however the hours are cut").**
- **Evidence:**
  - `declared_events_due` tests `_event_active` against `state.world_events` as it stood before the loop
    (`schedules.py:277-290`). Events found in this call are only in `out`.
  - Expiry runs once, before the call, at the end day (`clock.py:330-335`).
  - So a 48-hour sleep can draw the caravan on day 6 and again on day 7. Hour-sized steps cannot.
  - An event that expires mid-span suppresses draws it would otherwise allow.
  - `rumor_from` picks from the phase-tiered pool as of the span's end, not the day's.
  - `the_last_hour`'s `day` (and so its `expires_day` and first-seen day) is the first day in the span, not the
    day the reading crossed 1.0.
- **Fix:**
  - Track in-loop activity and per-day expiry for probabilistic events (an event drawn on day d is active through
    d+duration−1).
  - Either draw rumours per day against that day's phase, or state that the rumour tier is read at the step's end
    and drop rumours from the acceptance.

**I4. The conversion silently changes the effective rates. That is a balance change before measurement (§6.1
"0.25/day … as now", rule 10).**
- **Evidence:**
  - Today each legacy roll uses its per-day probability once per background tick (`schedules.py:360-361, 442-443`).
  - `simulate.py` ticks 2 h a turn at 3-5.6 h/turn (DESIGN.md § EvilTicker). That is several ticks per in-game
    day, so the caravan's effective rate is near 0.8/day and the press's near 0.15-0.2/day.
  - One draw per day at the same numbers makes the press about 5-6 times rarer. (Tinker scales by `days_elapsed`
    and is roughly unchanged.)
  - With 0.03/day from awareness 20, the first press has a median wait of about 23 days, and the levy needs a
    further 15. §10.2's "levy at max, median day 20-40" is then unlikely with the spec's own first values.
- **Fix:**
  - T1 measures the legacy per-day effective rates with `simulate.py` before converting.
  - Pick first values that preserve them, or record the change as a measured balance change with its lever.
  - Re-derive the levy row's first values from that measurement.

**I5. `simulate_decks.py --game clockwork-dark` cannot deal the flagship's cards (§4.3, §10.1).**
- **Evidence:** the walker never travels. It sets `location_id` to the entry once (`scripts/simulate_decks.py:183`)
  and walks days. Every flagship deck is gated by `at_location`, so "must deal every card" is unmeetable.
- **Fix:** measure card coverage in `simulate_doors.py`, as the union over its policies of the cards dealt and
  answered, and drop the deck-walker requirement for this story.

**I6. E5 already exists (§6.5, §13).**
- **Evidence:** `StoryValidator.check_set_pieces` (`engine/games/validation.py:2947-2992`, "`paths.challenges`
  (v0.17)") checks:

  - locations against the graph;
  - `requires`, flag lists and effects;
  - the challenge spec.
  `check_truncated_content` covers set-piece text, and `validate_content.py` and `doctor.py` both run
  `validate_story`. The README's "Known gaps" row is stale.
- **Fix:** strike E5 from the seams. T13 deletes the stale README row. Add a flagship set-piece case only if no
  test covers it (`set_piece_problems` is exercised in `tests/test_custody_predicate.py` and
  `tests/test_hue_and_cry.py`).

**I7. The endings overlay hides teases only in the client (§4.2 `tease:`, §8.4, Non-goal "hidden stats stay

- **Evidence:**
  - `endings.to_client` (`engine/game/endings.py:567-590`) ships `tease` for every tier. It also ships `title`,

**I8. The art assertions fail the release if T15 is deferred (§9, §17).**
