Status: **written 2026-10-23, revised the same day** after its opus review (0 Critical, 8 Important,
16 Minor; "Review rulings" at the end). Built without a per-design approval, as the owner
directs (CLAUDE.md, the 2026-09-26 re-cut). The owner's brief and decisions are the authority for WHAT is
built; they are kept verbatim in docs/superpowers/briefs/2026-10-13-sound-effects-brief.md.

v0.24.0 is three things, in this order of work:

1. **Sound effects** for the engine and all seven stories (§1-§11): alerts, ringtones, button presses.
2. **READ RECEIPTS' carried tail** (§12): the morning scene (v0.23.0 plan T24) and four more player
   life-event decks (T25), cut at v0.23.0's checkpoint C1 and moved here.
3. **v0.23.0's deferred close** (§13), run from the v0.23.0 plan at the END of this release: T29b, T31,
   T32 and T33.

Where this file and the code disagree later, the code wins (AGENTS.md authority order), and this file is
corrected.

**Rule 12.** Sound has nothing to do with content rating, and this design adds no rating layer of any kind:
no "intensity" of a sound, no per-content gating of a cue, no category a story's register can switch off. A
sound is chosen by an event and by the player's volume settings, nothing else.

## Goal

When v0.24.0 ships:

1. **Every story makes sound.** A button clicks, a choice answers, a turn arriving chimes, a roll rattles and
   then lands on its degree, an error and a dropped connection are heard. Each of the six non-phone stories
   sounds like itself (gears, glints, glitches, chips, latches); a story that declares nothing gets the
   engine's set.
2. **READ RECEIPTS sounds like a phone.** Messages pop in, a notification tone plays for a thread that is not
   open, typing ticks, sending whooshes, a voice note or a video message rings, the phone buzzes on the
   table while it is down, and locking, unlocking, picking it up and putting it down are all heard. The
   player picks the ringtone and the notification tone in the phone's own Settings app.
3. **The player is in charge.** A master volume, one slider per category, mute, and a quiet-interface mode;
   no sound before the first click or key press; nothing is lost when sound is off.
4. **The owner can audition everything.** One page lists every sound of the engine and each story, plays
   it, and shows its data key, so a change is asked for by name and made as a data edit.
5. **The morning after exists**, and the four remaining player life events have their world moments.
6. **v0.23.0 is closed**: balanced over full sessions, played live, documented and reviewed.

## Non-goals

- **No music, no ambience, no haptics, no positional audio** (NOT WIRED rows, §15).
- **No phone calls.** READ RECEIPTS' ringtones ring for an arriving voice note or video message (§9.7).
- **No server-side sound.** The server serves data and files only; the narration TTS is untouched.
- **No per-account sound settings** in hosted mode: they are the browser's, like every client preference.
- **No turn or phone payload change** (§6.3), and **no sound in the studio or the admin panel** (§15).

## §2 — The design in one page

- **Sounds are data**: the engine's in `content/sounds/sounds.yaml`, a story's under `paths.sounds`; a story
  declaring none gets the engine's set and byte-identical payloads.
- **`synth` sounds** (Web Audio oscillators, noise, envelopes, glides, filters, note sequences) carry every
  interface sound, chime, alert and ringtone; **`file` sounds** (Kenney CC0 Ogg clips) carry the foley that
  synthesis does poorly: dice, cards, coins, latches, cloth, doors.
- **Events, not call sites**: the client fires named events; the data binds each to a sound id, so a story
  re-voices an engine event by rebinding it and the owner's "softer dice" is a one-row edit.
- **One small client API** (`ui/src/core/sound/`), called directly where each thing happens, silent until
  the first gesture, sounding only NEW events (never a resume's or a rejoin's replay), one sound per action;
  **1 MiB** of audio in all; **an audition page** at `/?sounds=1`.

## §3 — Where sounds live

| What | Where | Served at |
|---|---|---|
| The engine's sounds | `content/sounds/sounds.yaml` (config `sound.root`, default `content/sounds`) | `GET /api/sounds` |
| The engine's files | `content/sounds/files/kenney/<pack>/<file>.ogg` | `GET /sound/_engine/<path>` |
| The engine's provenance and licences | `content/sounds/PROVENANCE.yaml`, `content/sounds/LICENSES/kenney-cc0.txt` | not served |
| A story's sounds | `paths.sounds` → `games/<slug>/data/sounds/` holding `sounds.yaml` | merged into `GET /api/sounds` |
| A story's files | `games/<slug>/data/sounds/files/...` | `GET /sound/<slug>/<path>` |
| A story's provenance | `games/<slug>/data/sounds/PROVENANCE.yaml` (only when it ships files) | not served |

`paths.sounds` is an ordinary manifest path key: `registry.validate` and `engine/games/validation.py` already
require a declared path to exist. A story's sound may reuse an engine file without copying its bytes:
`file: engine:files/kenney/casino-audio/dice-throw-1.ogg`.

**Config (rule 5)**, `config/default.yaml`:

```yaml
sound:
  enabled: true              # false: /api/sounds answers {enabled: false} and the client makes no effect sound
  root: "content/sounds"     # the engine's sounds.yaml, files and provenance
  cache_seconds: 3600        # Cache-Control: private, max-age on /sound/... files (behind a login when hosted)
```

The loader is `engine/games/sounds.py` (`load_engine()`, `load_story(slug)`, `merged(slug)`). Its cache is an
`lru_cache` keyed on `(slug, sounds path, sounds.yaml mtime)` as the other per-story loaders are (a manifest
dict is unhashable), classified `warmed` in `tests/fixtures/module_state.yaml` with its `WARMERS` row, and
reset through `engine/games/caches.py`'s `LRU_CACHES` (`cache_clear()`), not `NULLED_ATTRIBUTES`.

## §4 — The format

### 4.1 A file

```yaml
# content/sounds/sounds.yaml (the engine's) -- or games/<slug>/data/sounds/sounds.yaml
version: 1
limits: {voices: 8, throttle_ms: 60, roll_degree_delay_ms: 450}   # engine file only
events:                       # a STORY's own events (§5.2); the engine's are its closed list
  phone.ring: {label: "A voice note or video message arrives"}
sounds:
  ui.click:
    category: ui
    label: "Button press"
    synth:
      layers:
        - {wave: square, freq: 2200, to: 1400, glide_ms: 18, attack_ms: 1, decay_ms: 28, gain: 0.18,
           filter: {type: lowpass, freq: 5000}}
  roll.dice:
    category: game
    label: "Dice thrown"
    file: files/kenney/casino-audio/dice-throw-1.ogg
    gain: 0.7
bind:
  ui.press: ui.click
  roll.cast: roll.dice
  plate.reveal: null           # silent on purpose
  phone.ring: {default: ring.marimba, choices: [ring.marimba, ring.classic, ring.pulse]}
```

### 4.2 A sound

Common keys: `category` (required: `ui | game | alert | phone | world`), `label` (required: the audition
page's words), `gain` (0-1, default 1), `throttle_ms` (0-10000, default `limits.throttle_ms`), `essential`
(bool, default false: plays in quiet-interface mode, §7), `note` (free text for the audition page), and
exactly one of `synth` or `file`.

**`synth`** (all times in ms, the whole sound at most 4000 ms including repeats):

| Key | Meaning |
|---|---|
| `layers` | 1-6 voices played together. Each: `wave` (`sine square triangle sawtooth noise`), `freq` (20-16000 Hz; not for `noise`), `to` + `glide_ms` (an exponential glide), `detune` (cents), `start_ms`, envelope `attack_ms`, `decay_ms`, `sustain` (0-1, default 0), `hold_ms`, `release_ms` (default 20), `gain` (0-1), `filter` `{type: lowpass|highpass|bandpass, freq, q, to?, glide_ms?}`, `tremolo` `{rate_hz (1-60), depth (0-1)}` |
| `sequence` | `{voice: <one layer without freq>, notes: [[at_ms, pitch, length_ms], ...]}`: at most 32 notes; `pitch` is Hz or a note name (`E6`, `F#5`, `Bb4`). Ringtones, arpeggios |
| `repeat` | `{times: 1-4, gap_ms}` |
| `jitter_cents` | 0-100: a random detune per play, so a repeated click is not identical. Client-side `Math.random`, which is legal: nothing it touches is game state (rule 4 governs state) |

**`file`**: a path relative to the `sounds.yaml` directory, or `engine:<path>`; `.ogg` only, lower-case
(§8.2); `rate` (0.5-2, playback rate), `start_ms`, and a REQUIRED `fallback` (a `synth` block, §6.4). Every
file sound has one, so no browser ever loses a cue.

### 4.3 Bindings and merging

- An engine EVENT (§5.1) is bound in the engine file; every engine event must have a row (`null` allowed).
- A story file may: define new sounds; **override** an engine sound by defining the same id (the whole row
  is replaced, and the audition page marks it); **rebind** an engine event or one of its own; declare its
  own events (`events:`), each of which it must bind.
- A bound value is a sound id, `null`, or `{default, choices}` where every choice is a sound id of the same
  category as the default; the player's pick (§7) is a client preference.
- Merging is per story: engine sounds, then the story's sounds by id, then engine binds, then the story's.

### 4.4 Validation

`engine/games/sounds.py::check(data, *, where, story_events, engine_sounds)` refuses, naming the file and
the key: an unknown top-level, sound, layer, filter or sequence key; a value out of range; a sound with both
or neither of `synth` and `file`; a file sound with no `fallback`; a file path that is not lower-case, not
`.ogg`, not portable (`engine.names.is_portable_name`) or escapes its directory; **a file that does not
exist with EXACTLY that case**: every path component must appear, byte for byte, in its parent directory's
listing (`os.listdir`), not merely satisfy `Path.exists()`, which is case-blind on Windows and would pass a
name that 404s on Linux, Docker and CI (rule 11); an event bound to an unknown id; an engine event left
unbound; a story event declared and not bound or bound and not declared; a story event whose name starts with
an engine family (`ui. choice. turn. roll. alert. link. game. cutscene. encounter. panel. plate.`);
`choices` of mixed categories. Ids and event names match `^[a-z][a-z0-9_]*(\.[a-z0-9_]+)+$`.

`scripts/validate_content.py` (through `validate_story`) and `scripts/doctor.py` run it for every story that
declares `paths.sounds`, and the doctor checks the engine file once.

covers.

The panel events fire only where their payload key exists, which only a story declaring that system sends,
so they cost the others nothing.

### 5.2 A story's own

A story declares its events in its `sounds.yaml` `events:`; its PLUGIN's components fire them with the same
API as core (§6.3): `playSound(event, {key})` or `useSoundOnChange(value, event)`. There is no reducer hook
and no dispatch wrapper. The plugin lists every event it can fire in one new optional field, `soundEvents:
[...]`, which joins `ui/src/core/story.js`'s contract comment and `ui/tests/plugin-contract.test.js`, and is
kept when a plugin is borrowed (it is behaviour).

`tests/test_sound_events.py` maps each STORY to its plugin through its manifest's `ui.plugin` (a plugin is
not a story), reads that plugin's `soundEvents` as text, and requires every one to be declared in the
`events:` of the story whose own plugin it is; a story that borrows the plugin need not declare them. A borrowing story that
declares none of the events simply hears nothing for them. In vitest, `playSound` of an event the CURRENT
catalogue does not know throws only when the test installs a catalogue with `strict: true`; a test that
renders a borrowed plugin installs its own catalogue without it. Outside tests an unknown event is silent.

## §6 — The client

### 6.1 Modules

`ui/src/core/sound/`:

| File | What |
|---|---|
| `engine.js` | the `AudioContext` (created on the first gesture), the master bus and one `GainNode` per category, the voice cap (`limits.voices`, oldest stopped), per-sound throttle, the decoded-buffer cache, the Ogg probe, `setLevels(prefs)` |
| `synth.js` | `render(ctx, def, destination, when)`: oscillators, noise buffers, envelopes, glides, filters, tremolo and sequences from a §4.2 row; the note-name table |
| `catalog.js` | fetches `/api/sounds` once per page load; resolves event → sound id (the player's choice, else the default); file URLs; fallbacks |
| `turns.js` | the page's turn ledger (§6.3 rule 2) |
| `events.js` | `ENGINE_EVENTS` (§5.1), the list `tests/test_sound_events.py` compares |
| `index.js` | the API below; what stories import as `@core/sound` |

**The API** (the whole of it; every call site in §5 and §9 uses only this):

```js
playSound(event, { key, delayMs } = {})   // play now (or later); `key` de-duplicates (§6.3 rule 1)
markSeen(keys)                            // keys already on screen: they will never sound
useSoundOnChange(value, event, { when })  // a component hook: silent on mount, plays on a NEW value
                                          //   inside a turn this page asked for; `when(prev, next)` filters
turnSent()                                // the player sent a turn (core's choose, custom and begin handlers)
turnSettled()                             // App's busy-effect: true once for each turn this page sent
installClickSounds(root)                  // the delegated listener (rule 3)
useSoundLevels(prefs)                     // keeps the buses on the preferences
```

Core imports no story and names none (`tests/test_no_story_literals_in_core_ui.py` holds it).

### 6.2 Autoplay: nothing before the first gesture

No `AudioContext` exists until a user gesture. One cheap capturing listener on `pointerdown`, `keydown`,
`touchend` and `click` stays installed for the page's life: the first gesture creates the context and
`resume()`s it inside the handler; every later gesture calls `resume()` only when `context.state !==
"running"` (a background tab or iOS may suspend it). `touchend` and `click` matter: on iOS a `pointerdown`
from a touch does not grant activation. A `playSound` before the first gesture is DROPPED, never queued, so
the first click does not release a burst. A rejected `resume()` is caught and logged once.

### 6.3 Firing rules: direct calls, new events only, one sound per action

There is no dispatch wrapper and no reducer hook (owner ruling). Each sound is fired by a direct call at the
place that knows the thing happened (§5.1's middle column, §9's), through §6.1's API.

**Rule 1: only NEW events, de-duplicated.** A call with a `key` (a message id, a roll's `at`) plays at most
once per key; the seen-set is bounded (the 512 newest keys, oldest dropped) and lives for the page.
`markSeen(keys)` puts keys in it without a sound: READ RECEIPTS calls it with every message id in the phone
block on `game_started`, `game_resumed` and each rejoin before it sounds anything, so a resume, a rejoin, a
duplicate push or a `turn_update` that re-carries a message plays nothing.

**Rule 2: diff cues only inside this page's turns.** `turnSent()` is called by core's choose, custom and begin
handlers; App's existing busy-effect calls `turnSettled()` when `busy` goes from true to false, which
returns true once per sent turn. `turn.arrive`, the roll, the error, the ending, the cutscene, the
encounter, the panel cues and every story's `useSoundOnChange` sound only for state that arrived inside such
a turn. A component's `useSoundOnChange` records its value silently on mount and on hydration
(`game_started`, `game_resumed`, a rejoin, `RESET`), so a run loaded at phase "consuming", with a wanted
level of 3 or an ending showing, is silent. A rejoin's replayed turn is never a sent turn.

**Rule 3: one action, one sound.** The delegated listener plays `ui.press` (or `ui.toggle`) for a control
with no `data-sound`. A control whose action has its own event carries `data-sound="none"`, and its HANDLER
fires that event, so the click and the keyboard path (Enter, a digit key) sound the same: the choice buttons
(`choice.pick`), the compose and phone send buttons (`choice.send`, `phone.send`), the pause menu's "Write"
(`game.save`), the begin button (`game.begin`), READ RECEIPTS' lock, raise and swipe controls. A failed
action plays its error (if any), never its success sound. READ RECEIPTS' own overlaps are §9.7's.

### 6.4 Files and fallbacks

Once, at the first gesture, the engine probes `new Audio().canPlayType('audio/ogg; codecs="vorbis"')`. When it
answers `""`, every file sound plays its `fallback` synth and no file is ever fetched; WebKit may not decode
Ogg Vorbis (iOS, where every browser is WebKit, matters for hosted READ RECEIPTS), and the design does not
depend on which versions do. Otherwise a file is fetched and decoded the first time its sound is played and
kept for the page's life; a fetch or `decodeAudioData` failure plays the fallback, with one `console.warn` per
sound id. The narration `<audio>` element stays as it is, its volume now `master x narration` (§7).

### 6.5 A play log for verification

With `?soundlog=1` the engine keeps a ring buffer of the last 200 calls (`{t, event, sound, category, key,
fallback?: true, dropped?: "locked"|"muted"|"throttled"|"quiet"|"seen"|"not_my_turn"}`) on
`window.__clockworkSoundLog`. An agent driving the browser pane cannot hear; T12's walk (§13) reads this log
to confirm each cue fired once, and the owner listens.

row. Quiet interface is the "reduced sound" mode for a player who finds clicks wearing. No sound repeats
more often than its throttle (READ RECEIPTS' typing tick: one per 4 s). Nothing flashes in place of a sound.

## §8 — CC0 files: sources, provenance, budget

### 8.1 Sources

**Kenney (kenney.nl), CC0 1.0 Universal**, one author, each pack carrying its own `License.txt`. Only these
packs, downloaded as their zip from the asset page:

| Pack | Page | Files taken (as named in the pack; confirmed at import) |
|---|---|---|
| Casino Audio | https://kenney.nl/assets/casino-audio | `dice-throw-1.ogg`, `card-slide-1.ogg`, `card-place-1.ogg`, `chips-stack-1.ogg` |
| RPG Audio | https://kenney.nl/assets/rpg-audio | `metalLatch.ogg`, `handleCoins.ogg`, `bookFlip1.ogg`, `doorOpen_1.ogg`, `doorClose_1.ogg`, `cloth1.ogg`, `cloth2.ogg` |
| Impact Sounds | https://kenney.nl/assets/impact-sounds | `impactBell_heavy_000.ogg`, `impactWood_light_000.ogg` |
| Sci-fi Sounds | https://kenney.nl/assets/sci-fi-sounds | `computerNoise_000.ogg`, `forceField_000.ogg` |

Fifteen files, every one bound in §9 (review M8: the unbound four are not imported). If a named member is
absent, or is over the 48 KiB cap (§8.3: a file cannot be shrunk without transcoding), T7 takes the nearest
file in the SAME pack and records the substitution; anything outside these four packs needs a spec change.
If kenney.nl cannot be reached, OpenGameArt's Kenney mirrors of the same packs are the fallback source,
recorded as such.

**Why Kenney alone.** One CC0 author with a licence file in every archive makes provenance provable. Freesound
is rejected: downloading needs an account (which an agent may not create) and its licences vary per file.
Sonniss bundles and the BBC library are not CC0.

**Downloads.** The owner's standing approval covers them (memory: downloads approved); a permission prompt
may still ask. Each zip goes into its own new scratch directory and is treated as untrusted data:
`scripts/import_sounds.py` (run with `python -I`, the zip's path passed as an argument) reads the named
members with `zipfile` without extracting the rest and runs nothing from the archive.

### 8.2 Import and provenance

`scripts/import_sounds.py --archive <zip> --pack <name> --page <url> --member <path> [--member ...] --to
<sounds dir>` copies each member byte-for-byte to `files/kenney/<pack>/<basename>`, **always lower-casing
the basename** (`metalLatch.ogg` → `metallatch.ogg`, rule 11), records the member's original case in `member`,
and appends its row:

```yaml
# content/sounds/PROVENANCE.yaml
files:
  - path: files/kenney/casino-audio/dice-throw-1.ogg
    sha256: <64 hex>
    bytes: 13824
    author: "Kenney (www.kenney.nl)"
    pack: "Casino Audio"
    source_url: "https://kenney.nl/assets/casino-audio"
    archive: "kenney_casino-audio.zip"
    archive_sha256: <64 hex>
    member: "Audio/dice-throw-1.ogg"
    licence: CC0-1.0
    licence_file: LICENSES/kenney-cc0.txt
    downloaded: 2026-10-24       # the archive's download date
    pack_version: "1.0"          # when the asset page shows one; omitted otherwise
    imported: 2026-10-24
```

The pack's own `License.txt` is copied once to `LICENSES/kenney-cc0.txt`. No transcoding: the shipped file is
the pack's own bytes, so its sha256 can be checked against the archive again at any time. Credit is not
required by CC0; the README's credits line names Kenney anyway.

### 8.3 Format and budget

- **Ogg Vorbis**, as the packs ship it, never transcoded. Chrome, Edge and Firefox decode it; WebKit may
  not. Every file sound therefore carries a synth fallback (§4.2), chosen up front by the `canPlayType`
  probe (§6.4). AAC twins are rejected: transcoding, twice the bytes and derived-file provenance.
- **1 MiB (1,048,576 bytes) for ALL shipped audio**, engine and stories together, and **48 KiB per file**,
  checked by `tests/test_sound_budget.py`. Justification: synthesis carries every interface sound, alert and
  ringtone at zero bytes, so files are only the fifteen foley clips above, which run 5-30 KB each in these packs:
  about 0.3-0.4 MB, leaving room for the four overhauls (v0.25.0-v0.28.0) to add their own without a budget
  change. The brief's suggested 2 MB is more than the design needs; a smaller cap is cheaper to keep in a
  committed tree and in the 327 MB Docker image, and the per-file cap stops a stray stereo WAV.
- Over 48 KiB, a file is replaced by another member of its pack (§8.1). A file's first bytes must be `OggS` and its Vorbis identification header must say at most 2 channels and
  at most 48 kHz (the budget test reads both).

## §10 — Server routes, hosted mode, platforms

**Routes** (`engine/api/sounds.py`, a blueprint factory registered beside the art blueprint):

- `GET /api/sounds` → the running story's merged catalogue: `{enabled, limits, events, sounds: {id: row with
  file rows' url resolved}, bind}`; with `sound.enabled: false`, `{enabled: false}`.
- `GET /api/sounds/catalog` → `{engine: {...}, stories: [{slug, title, declares, events, sounds, bind,
  overrides: [ids]}]}` for the audition page: every registered story locally; in hosted mode the stories in
  `hosting.stories`.
- `GET /sound/<scope>/<path>` → a file: `scope` is `_engine` or a story slug that declares `paths.sounds`
  (in hosted mode, also one in `hosting.stories`; any other slug 404s, matching the catalog route); the path
  is resolved under that root with the traversal check `send_generated` already makes (`engine/api/media.py`),
  served with an explicit `mimetype="audio/ogg"` (the Windows registry may map `.ogg` otherwise) and
  `Cache-Control: private, max-age=<sound.cache_seconds>`; anything else 404.

**Hosted mode.** These are static data and files: every route sits behind the hosted gate's one
`before_request` (not in its `OPEN` table), reaches the worker through the front door's proxy, and needs no
per-account state; settings stay in the browser. No audit row, no metric, no admin page.
`tests/test_hosting_gate.py` and `tests/test_hosting_secrets.py` already walk every URL rule, so they cover
the three new ones; `tests/test_admin_no_play_text.py` is unaffected.

**Local-mode golden** (`tests/test_local_mode_golden.py`). Two sanctions, each exact and each asserted to
apply, in the file's existing style:
- **S12**: `paths.sounds` added to the five recorded rows of the declaring stories in `games.json` (flagship,
  Garden, NEON CITY, THE LONG CON, HUE & CRY) and to `games_active.json`, `games_clockwork-dark.json` and
  `games_hue-and-cry.json`; READ RECEIPTS' row is S11's `READ_RECEIPTS_ROW` constant, edited in place by
  precedent (its comment lists T10, T11, T23F, T26; T4 adds itself). `dev-story`'s row does not move.
- **S13**: exactly three `url_map` rows, with their endpoint names, in `app_shape.json`; the test also
  asserts that no `before_request` or `after_request` row moves (the fixture holds no blueprint list).

No turn, save, settings or art fixture moves.

**Platforms (rule 11).** The server only reads YAML and serves bytes; paths are joined with `pathlib` and
checked portable; every shipped file name is lower-case and every reference is checked against the
directory listing with exact case (§4.4); `import_sounds.py` is pure Python (no `ffmpeg`, no shell),
run the same way on Windows and Linux. No sound value reaches game state, so `detmath` is not involved.

## §11 — The audition page

`/?sounds=1`: `main.jsx` lazy-loads `ui/src/core/sound/Audition.jsx` and its CSS, as it does the studio. It
reads `/api/sounds/catalog` and draws:

- an **unlock bar** ("Click anywhere to turn sound on") until the first gesture (§6.2);
- a **master slider** and mute, on the same `clockwork_prefs`;
- a **filter box** (matches an id, an event, a label or a category);
- one **section per scope**: "Engine", then each story by title, a story that declares nothing shown as
  "Uses the engine's sounds";
- in each section, one **row per sound**: ▶ play, the label, the category, the events it is bound to, the
  source (`synth`, or the file with its pack, author and licence from `PROVENANCE.yaml`, which the catalog
  route includes for file rows, marked "fallback" on a browser whose Ogg probe failed, §6.4), "overrides the
  engine's" when it does, and its **data key** in full, e.g.
  `games/read-receipts/data/sounds/sounds.yaml › sounds › ring.marimba`, with a copy button; a synth row
  expands to show its parameters as YAML;
- a **"Play each"** button per section, one sound a second.

Each play goes through the same engine as the game (so throttles and categories apply, and `?soundlog=1`
logs it). The pause menu and the Settings overlay link to it. The page is keyboard-reachable (rows are
buttons; `/` focuses the filter) and joins `npm run layout-check` at the four sizes (no horizontal page
scroll; every play button reachable).
