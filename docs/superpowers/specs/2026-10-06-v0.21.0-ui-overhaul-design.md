## Goal

1. **The shared client works for every story, not only for the four that
   ship a plugin.** The survey (below) found the play screen's layout
   positional and fragile, and three whole surfaces — the scene picture,
   the dice receipt, the encounter's legal approaches — drawn only by the
   flagship's plugin, so a story on the engine's own skin (`_engine`:
   HUE & CRY, Dev Story) receives them over the socket and shows nothing.
2. **The shared surfaces are built once, as engine panels** that a story
   enables by DATA — the payload key its declared systems send, and an
   optional `ui.panels` list in its manifest — never by story-specific
   code in core (rule 5): the wanted poster, the job panel, the casing
   board, the people here with their portraits, the encounter's approaches
   and the roll card.
3. **HUE & CRY's screens** are those panels, worn under a thin skin of its
   own (wax and parchment, a seal-red accent), with no slot overridden.
4. **The connection survives the server.** The client reconnects after a
   server-side close, rejoins its run without double-resuming it, respects
   hosted auth (a dead login goes to the login page, never loops), and says
   what is happening.
5. **Three carried removals and one carried fix**: the `lmstudio:` config
   alias and `stack.services.lmstudio`, the `paths.saves` config alias, the
   `engine.lmstudio` shim; and the Settings panel's `config_path` row when
   the settings are not writable.
6. **New README screenshots**, captured the same way every time.

**What does not move.** No prompt, no narration request, no save file, and
no turn payload of a story that does not declare `paths.law` or
`paths.jobs`. The local-mode golden moves by exactly four sanctioned
transforms (§1.2). The LM Studio golden's recorded requests and responses
do not move at all; only its harness's input config is renamed (§1.3).

## Non-goals

- **No new story mechanics, and no balance change.** Every panel renders
  what the engine already decides. `scripts/simulate.py` is not re-run for
  a balance reason because no constant changes (rule 10).
- **The other stories' overhauls** (v0.23.0–v0.26.0). The flagship,
  the Garden, NEON CITY and THE LONG CON keep their plugins and their look;
  they change only where a core fix reaches them (§3, §4.6, §6, §8), each
  recorded in that story's CHANGELOG.
- **HUE & CRY's art pack** (v1.0.0, ~55 Grok plates). Portraits render
  through the existing art pipeline (`paths.art_manifest` `portraits:`),
  which is empty for HUE & CRY today; the people strip draws a monogram
  until the plates land, and lights up with no code change when they do.
- **A player's place in the model server's queue** (docs/GOVERNANCE.md,
  "A player's place in the model server's queue"). It needs a per-waiter
  event on every queue move across the supervisor's bus; v0.21.0's
  connection work is already the riskiest part of the release. The row
  stays NOT WIRED and loses its "until v0.21.0" promise.
- **Hosting under a URL sub-path, a per-story Socket.IO path, and two
  stories in two tabs of one browser** (GOVERNANCE rows of the same names).
  All three need a configurable client base and a `SCRIPT_NAME`-aware
  front door, which is hosting work, not UI work. Rows stay, re-dated to
  "a later release".
- **The admin panel inside the React client.** It stays server-rendered
  (v0.20.0 T14); the GOVERNANCE row is updated to say v0.21.0 decided so,
  and why: the panel must stay free of the client's build and its HTML
  sinks (`tests/test_ui_no_html_injection.py`).
- **Local mode's two-tabs finding** (CLAUDE.md, "Two tabs can drive one
  local session"). Unchanged; §6.3 is designed so the reconnect never
  CREATES that situation, which is the part that is v0.21.0's business.
- **No new runtime dependency, and one devDependency.** No `axe-core`, no
  router, no browser download. The one addition is `playwright-core`
  1.48.2 for the screenshot script (§11), a download that waits for the
  owner's consent at T5.
- **No content-rating or "safety" layer in any form** (rule 12). No panel,
  setting or onboarding card says anything about how explicit a story is.

## Findings the survey turned up

Each is a defect in shipped code, with the evidence that proves it. Each
section below cites the finding it fixes.

**F1 — The play screen's rows are positional, and any optional panel can
take the narrative log's row.** `.scene__col--main` gives its FIRST two
children the two flexible tracks
(`ui/src/styles/index.css:443-449`, `minmax(var(--visual-height),
var(--row-visual)) minmax(var(--log-min), var(--row-log))`, 6fr and 4fr
by `ui/src/styles/spacing.css`) and everything after them an `auto` row.
The comment above it assumes those children are "still-or-encounter, then
log". They are whatever renders first: `Stage` is optional
(`ui/src/core/screens/Play.jsx:140`), then `BeatFrame` (`:142`, null
unless a challenge or a deck is live), then the log (`:144`), the
reasoning panel, the negotiation panel (`:163`) and the casing board
(`:167`). On `_engine` (no `Stage`) the LOG takes the picture's 60% row
and whichever optional panel happens to render next takes the log's 40%
row with a 7rem floor. A grid item in a fixed-size track overflows the
track and paints over the next row. This is the casing board overlapping
the choice list (CLAUDE.md:568, "seen in v0.19.0 T9"): on a HUE & CRY turn
with no reasoning text and no pipeline negotiation, the casing board is the
second child, gets the `minmax(7rem, 4fr)` track, and a district of five
houses with learned lines is taller than that. On the flagship the same
shape bites whenever a deck or challenge is live: `BeatFrame` becomes the
second child and takes the log's row, and the log drops to `auto`.

**F2 — On the engine's skin, three surfaces the server sends are never
drawn.** `dice_result` is rendered only by the flagship's `Toast`
(`ui/src/stories/clockwork-dark/index.jsx:184-186`; no other plugin
mentions dice). The scene picture (`image_ready`, `opening.scene_image`,
reduced into `state.sceneImage` at `ui/src/core/store.js` `image_ready`)
is drawn only by a plugin's `Stage`; `_engine` has none
(`ui/src/stories/_engine/index.jsx:17-20`), so HUE & CRY's procedurally
generated plate (`tests/fixtures/local_mode/hue-and-cry/socket_turns.json`,
an `image_ready` with `/api/media/images/*.svg`) is fetched and discarded.
An encounter's engine-authored approaches (`world.encounter.approaches`,
the `watch_stop` rows in `tests/fixtures/local_mode/hue-and-cry/state.json`)
are drawn only by the flagship's and NEON CITY's `Stage`s — and both of
those send a pressed approach as TYPED text (`onCustom(approach.text)`,
`clockwork-dark/index.jsx:163-168`), which carries no intent by definition
(`engine/scenes/default_state.py:640-651`, "Typed input declares no intent
by definition"), so the press resolves nothing unless the model reaches
for the MCP tool path, off by default and LM Studio-only. While a scene is
open the engine offers ONLY the `encounter` verb (`engine/game/intents.py:
872-883`), so the narrator's choices are the intent-bearing approaches —
and the flagship hides them (`hideChoices`). That is a rule-1 defect, fixed
in §4.5 (Review 1). NEON CITY, THE LONG CON and the Garden also never show
a roll. This is the audit's "reached but unnarrated" class with the player
as the reader: the receipt exists and nobody sees it.

**F3 — The client never reconnects after a server-side close, and its
status line says it is.** `connect()` (`ui/src/core/socket.js:80-96`)
relies on Socket.IO's own reconnection, which does not run after a
disconnect whose reason is `"io server disconnect"` (the server closed the
socket: hosted mode's `SocketDoor.drop`, `engine/hosting/sockets.py:254-263`,
on a password change, a disable, or a stale login). The footer then reads
"Reconnecting…" forever (`ui/src/core/parts/Chrome.jsx:190-191`), and on a
phone that text is hidden entirely: under 560px the status is a 10px dot
with its words indented away (`ui/src/styles/index.css:3429-3437`).
`connect_error` dispatches `ERROR` with Socket.IO's own words ("xhr poll
error", "websocket error") once per retry (`socket.js:92-95`), which also
closes any stream in progress. A hosted login that has ended is
indistinguishable from a server that is down: the WebSocket door's 401
(`engine/hosting/frontdoor/ws_relay.py:312`) reaches the browser as an
opaque "websocket error".

**F4 — A reconnect always RESUMES, which rebuilds the session under the
same id.** `App.jsx:102-107` emits `resume` with the stored save id on
every `connect`, first or not. After a transport blip the session is still
live on the server, and `SessionStore.resume` rebuilding it is exactly the
two-tabs mechanism (CLAUDE.md, "Two tabs can drive one local session": a
turn in flight on the old engine can autosave over the new session's
state). The server already has the right door: `join_session` re-joins a
LIVE session's room and answers `game_started` with `opening:
session.last_turn` (`engine/scenes/default_scene.py:535-555`), which is
the last turn's full payload, prose included.

**F5 — While disconnected, every control stays live.** `DISCONNECTED`
clears `busy` (`ui/src/core/store.js`, `case "DISCONNECTED"`) and nothing
else disables a choice. Socket.IO BUFFERS an emit made while disconnected
and sends it on reconnect, before the client has re-joined its room: the
turn runs, its stream goes to a room the new socket is not in, and the
player sees nothing.

**F6 — A hosted run released elsewhere goes quiet with no word.** One live
run per account (spec v0.20.0 §5.4): a resume in another tab releases this
one (`engine/session/store.py:555-562`), and the release hook only closes
the Socket.IO room (`engine/hosting/__init__.py:197-200`). An admin's end
(`store.py:764-765`) and the idle sweep (`store.py:912-918`) are the same.
GOVERNANCE.md has two rows waiting for "v0.21.0's UI" on this.

**F7 — The save browser speaks the flagship's fiction for every story,
and drops what the story declared.** `Saves.jsx:11-16, 73-75` prints
"the pattern is quiet" from `save.evil_phase` for every row — on
HUE & CRY's saves too, whose `evil_phase` is the GameState default
`"dormant"` (`tests/fixtures/local_mode/hue-and-cry/save_list.json`). It
prints `archetype` and `location_id` raw ("cutpurse", "tallow docks"). And
the server's story-declared columns (`SaveSummary.values`,
`engine/persistence/saves.py:134-160`, projected from `state.yaml`
`summary:` for Dev Story, NEON CITY, THE LONG CON and the Garden) are sent
and never rendered: no file under `ui/src` reads `values`.

**F8 — Settings shows an empty path and live write buttons where nothing
can be written.** Hosted `GET /api/settings` omits `config_path` and adds
`writable: false` (`engine/api/settings.py:678-685`). `Settings.jsx:294-300`
renders `<code>{spec.config_path}</code>` (empty) and "Reset to defaults" /
"Apply" stay enabled (`:224-230`), so a hosted player can press a button
the server refuses. The success line hardcodes `config/local.yaml`
(`:191`) whatever `config_path` says.

**F9 — Focus is thrown away on every turn.** A chosen chip is
`disabled={busy}` (`ui/src/core/parts/ChoiceRow.jsx:78`), so the button
holding focus becomes disabled and the browser moves focus to `<body>`. A
keyboard or screen-reader player loses their place on every choice. The
compose box does the same (`Play.jsx:193`).

**F10 — The compose placeholder is a keyboard hint on a phone.**
`Play.jsx:192`: "(press / to jump here, Esc for the menu)" on a touch
screen with neither key.

**F11 — The casing board's heading skips a level.** `CasingBoard.jsx:36`
is an `<h3>` under the page's `<h1>` (`Chrome.jsx`, the place name) with no
`<h2>` between; the negotiation panel does the same.

**F12 — The poster and the job panel have words and no order.**
`_law_block` sends wanted bands and the clarity word
(`engine/game/state.py:676-734`); `_job_block` sends the alarm and prep
bands (`:736-779`). The words are authored per story
(`games/hue-and-cry/data/rules/law.yaml:259`, `wanted.bands`; HUE & CRY
declares no `clarity_words`, so it uses `law.DEFAULT_CLARITY_WORDS`,
`("nothing", "a rumour", "a description", "a likeness")`,
`engine/world/law.py:96` — Review 13;
`games/hue-and-cry/data/rules/jobs.yaml:235-248`), so the client cannot
know that "sought" is worse than "noticed", and a poster whose sketch
"sharpens as the watch's precision rises" (HUE & CRY spec §6) has nothing
to sharpen by.

## §2 — Engine panels: the framework

### 2.1 What a panel is

A **panel** is a core React component, registered in one table
(`ui/src/core/panels/registry.js`), that renders one engine system's data
in one **region** of the play screen. It reads only the store (the turn
payload as reduced) or one read-only route, renders `null` when its data is
absent, and never acts except through the existing `onCustom`/`onChoose`
(an encounter approach is an ordinary turn, as the flagship's already is:
`clockwork-dark/index.jsx:155-170`). Panels are story-agnostic: every word
on one comes from the payload or from core's own neutral labels ("Wanted",
"The job", "Casing", "Here").

The registry, in full:

| id | Region | Enabled by | Data | Component |
|---|---|---|---|---|
| `wanted` | `ledger` (+ a chip in `header`) | **data**: `world.law` present | `law` block (§4.1) | `WantedPoster`, `WantedChip` |
| `job` | `shelf` | **data**: `world.job.active` non-null | `job` block (§4.2) | `JobPanel` |
| `casing` | `ledger` | **data**: `world.premises` present and non-empty | `premises` (+ `job.prep`) (§4.3) | `CasingBoard` (moved) |
| `negotiation` | `shelf` | **data**: `state.negotiation.ran` | `negotiation` | `NegotiationPanel` (moved) |
| `rolls` | `toast` | **data**: a `dice_result` this turn | `dice_result` (§4.6) | `RollCard` |
| `people` | `stage` | **declared** only | `GET /api/people` (§4.4) | `PeopleStrip` |
| `encounter` | `shelf` | **declared** only | `world.encounter.approaches` (§4.5) | `EncounterPanel` (core) |

Five regions, each a fixed place in the frame (§3): `header` (beside the
story's `HeaderBadge`), `stage` (inside the stage area, under the `Stage`
slot), `shelf` (between the log and the choices), `ledger` (inside the
sheet column, under the `Ledger` slot), `toast` (the floating layer, beside
the `Toast` slot).

**Decision: data-gated panels are on by default; the two that are not are
opt-in.** A data-gated panel can only appear for a story that declares the
system feeding it — DECLARATION IS THE SWITCH, the payload convention
(`engine/game/state.py:587-593`) — so "on by default" adds nothing to a
story without that system. That is how the casing board already works
(`Play.jsx:165-167`). `people` and `encounter` are different: every story
declares people (all six declare `paths.npc_schedules`), and three plugins
already draw encounters, so turning them on by default would change every
story's look in a release that is not their overhaul. They are opt-in.

### 2.2 What a story writes: `ui.panels`

```yaml
# games/<slug>/game.yaml
ui:
  plugin: _engine          # unchanged meaning (docs/AUTHORING.md §2.5)
  panels:                  # optional. Omitted: the data-gated defaults.
    - wanted               # a bare id: its default region
    - casing
    - job
    - id: people
      region: stage        # a mapping: the id and, optionally, a region
    - encounter
```

Semantics, exactly:

- **Omitted** — every data-gated panel (`wanted`, `job`, `casing`,
  `negotiation`, `rolls`) in its default region, in registry order; no
  opt-in panel. This is what five of the six stories get.
- **Present** — exactly the listed panels, in the listed order within each
  region, and nothing else. `panels: []` turns every core panel off.
- **`region:`** — one of `header`, `stage`, `shelf`, `ledger`, `toast`,
  restricted per panel to the regions it is drawn for: `wanted`
  {`ledger`, `shelf`}, `job` {`shelf`, `ledger`}, `casing` {`ledger`,
  `shelf`}, `negotiation` {`shelf`}, `rolls` {`toast`}, `people`
  {`stage`, `ledger`}, `encounter` {`shelf`}. The `wanted` chip always
  goes in `header` with the poster and cannot be placed alone.
- A listed panel whose data is absent renders nothing, like any panel.

**Validation** (fail at activation, like every other manifest key; and
`scripts/validate_content.py` and `scripts/doctor.py` through the same
check):

- ERROR: an unknown id, a duplicate id, a region the panel is not drawn
  for, a non-list `panels`, an entry that is neither a string nor a
  mapping, a mapping with a key other than `id`/`region`.
- ADVISORY: a data-gated panel listed by a story that does not declare its
  system (`wanted` without `paths.law`, `job` without `paths.jobs`,
  `casing` without `paths.premises`, `encounter` without
  `paths.encounters`): it will never render.

The legal ids and regions live once in Python
(`engine/games/manifest.py::UI_PANELS`, `{id: (default_region,
allowed_regions, gate)}`) and once in the client registry; a test reads the
client registry as text (as `tests/test_ui_contract.py` reads `INBOUND`)
and fails when the two disagree.

**How it reaches the client.** The catalogue row already carries the raw
`ui` mapping (`games.json`: `"ui": {"plugin": "_engine"}` beside
`"ui_plugin"`). `resolveStory` (`ui/src/core/story.js:254-279`) reads
`active.ui.panels` and `loadStory` puts it on the story object as
`story.panelDeclaration` (`undefined` when omitted). **Decision: the
declaration is data from the manifest, never a plugin field**
(`ui/tests/plugin-contract.test.js` gains an explicit assertion that no
plugin exports `panelDeclaration`, because its slot harvest would
otherwise accept any `story.X` core reads — Review 24) — one source,
written against AUTHORING, not engine source; a borrowed plugin cannot lend
or strip it, because it is not the plugin's.

### 2.3 What a plugin may say: `ownsPanels`

A plugin that draws a system itself declares it, so core does not draw it
twice:

```js
export default { /* ... */ ownsPanels: ["rolls", "encounter"] };
```

The resolved set is the declaration (or the defaults) minus `ownsPanels`.
The flagship sets `["rolls", "encounter"]` (its `DiceToast` and
`EncounterPanel`); NEON CITY sets `["encounter"]` (its `Stage` draws the
approaches: `neon-city/index.jsx:114-121`). `ownsPanels` is a visual slot:
**kept** when a plugin is borrowed (the borrower inherits the drawing, so
it must inherit the claim), added to the contract comment in `story.js`,
and harvested by `ui/tests/plugin-contract.test.js` like every other slot.

**Decision: an approach is pressed as the narrator's intent-bearing
choice, and only matched choices are hidden** (Review 1, controller
ruling). The client cannot author an intent: `player_choice` carries a
`choice_id`, and the server resolves the intent from the options it
actually showed (`resolve_player_intent`, `default_state.py:640-651`), and
typed text resolves to none. While a scene is open the engine offers the
narrator ONLY `encounter` intents (`intents.py:872-883`), so each legal
approach the narrator offered arrives as a choice with `intent: {action:
"encounter", target: <approach id>}`. One core helper,
`ui/src/core/panels/approaches.js::matchApproaches(encounter, choices)`,
pairs each approach with the choice whose `intent.action === "encounter"
&& intent.target === approach.id`:

- a matched approach's button calls `onChoose(choice)` — the ordinary
  choice path, so the engine runs `encounter_approach` before narration
  (rule 1);
- an unmatched approach is drawn, not pressable, with the word "not
  offered this turn" (`aria-disabled`);
- core's derived `hideChoices` hides exactly the MATCHED choices, so any
  narrator choice that is not an approach (and every choice when nothing
  matched) stays visible;
- no core path ever sends an approach through `onCustom`.

The flagship's and NEON CITY's own approach buttons
(`clockwork-dark/index.jsx:163-168`, `neon-city/parts/Stage.jsx:148`) and
their `hideChoices` (`clockwork-dark/index.jsx:188-193`,
`neon-city/index.jsx:118-121`) are changed in the same task to use
`matchApproaches` the same way. It is a rule-1 fix, not a look: their
buttons and layout are unchanged. A plugin's own `hideChoices` still wins
when present.

## §3 — The play-screen layout

### 3.1 Named areas, not child positions (F1)

`.scene__col--main` becomes a grid of NAMED areas; every child is placed by
name, so what renders, and in what order, can no longer move a row:

```css
.scene__col--main {
  display: grid;
  grid-template-areas: "stage" "frame" "log" "think" "shelf" "choices" "compose";
  grid-template-rows:
    minmax(var(--visual-height), var(--row-visual))  /* stage */
    auto                                              /* frame: BeatFrame */
    minmax(var(--log-min), var(--row-log))            /* log */
    auto                                              /* think: reasoning */
    auto                                              /* shelf (T9: was minmax(0, auto), whose 0 base ignored the 44px floor) */
    auto                                              /* choices */
    auto;                                             /* compose */
}
.scene__col--main[data-stage="off"] { grid-template-rows: 0 auto minmax(var(--log-min), 1fr) auto auto auto auto; }
.stage-area { grid-area: stage; }  .beatframe { grid-area: frame; }  .log { grid-area: log; } /* ...one rule per area */
```

`Play.jsx` wraps each region in a fixed element (`.stage-area`,
`.shelf`) whether or not it has content, so an empty region is an empty
named cell, never a missing child. `data-stage="off"` is written only when
neither a plugin `Stage` nor core's default (§3.3) renders.

**Empty areas cost nothing (Review 11).** An empty grid track still takes a
`gap` on each side, so seven fixed tracks would spend six gaps (~72px)
whatever renders. The column therefore has `row-gap: 0`, and spacing is a
margin on content: `.scene__col--main > :not(:first-child):not(:empty)
{ margin-block-start: var(--space-3); }`, with every region wrapper
rendering no children (`:empty`) when it has nothing to show. An empty
`frame`, `think` or `shelf` is a zero-height track with no margin.
*Built (T6) with the plan's selector, `.scene__col--main > :not(:empty) ~
:not(:empty)`: the first NON-EMPTY area takes no margin, so a stage-less
column's log does not start 12px down.* *The margin sits inside the log's fr
track (the gap sat outside both), so a 60/40 story measures ~61.6/38.4
(276/172px at 1366x768): accepted by the controller as part of the new
margins (T6 review finding 4).*

### 3.2 The shelf is bounded (the overlap)

### 4.1 The wanted poster (`wanted`)

**Problem.** The Law ships a poster's worth of data and nothing draws it
(GOVERNANCE.md, "Wanted-poster UI chrome"); the words carry no order (F12).

**Data contract.** `world.law`, from `GameState._law_block`
(`engine/game/state.py:676-734`), gains one key:

```jsonc
"law": {
  "guise_label": "the Magpie's mask",
  "wanted":  {"the Quay": "sought", "the Wick wards": "unknown", "up the Rise": "noticed"},
  "clarity": "a description",          // "nothing" on a new run (new_game.json)
  "custody": null,                     // or {fine, fine_text, days}
  "scales": {                          // NEW: display order, low to high
    "wanted":  ["unknown", "noticed", "sought", "wanted", "hunted"],
    "clarity": ["nothing", "a rumour", "a description", "a likeness"]
  }
}
```

`scales.wanted` is `law.load_spec()["wanted"]["bands"]`; `scales.clarity`
is the list `law.clarity_word` indexes (`law.py:669`): the story's
`clarity_words`, or `DEFAULT_CLARITY_WORDS` (`law.py:96`) — HUE & CRY
declares none, so it gets the default four, "nothing" first (Review 13).
**A word not in its scale** — `band_for` returns `""` below the first
threshold or with no bands (`law.py:595-602`) — renders as its text (or
nothing, for `""`) with zero marks lit, and never counts as the worst band. Both are authored
words, already public through the bands they order. **The veiled rule
holds**: an index into a scale is used to light glyphs and to pick a
sketch layer, never printed and never turned into a percentage, exactly as
`Meters.jsx:35-38` uses the veiled band order.

**Design.** In the ledger, under the sheet: a poster card.
- Heading "Wanted" (core's word), then the guise label large ("the
  Magpie's mask") — the face the watch is looking for, which is the
  face currently worn.
- **The sketch.** A core SVG head-and-shoulders, drawn in four stroke
  layers (frame; outline; features; hatching). With N clarity words and
  index i, layers shown = `1 + round(3·i/(N−1))`, so the first word shows
  only the frame and a "?" and the last a full likeness. For HUE & CRY's
  N = 4 that is exactly one layer per word: "nothing" 1 (frame and "?"),
  "a rumour" 2, "a description" 3, "a likeness" 4. The clarity word
  under it ("a description"). The SVG is `role="img"` with
  `aria-label="The watch here has a description of the Magpie's mask"`.
- **The bands.** One row per jurisdiction, in payload order: its label,
  its band word, and a glyph row of N−1 marks lit to the band's index
  (`aria-hidden`).
- **Custody.** When `custody` is non-null, the card is stamped "Held" and
  reads "A fine of {fine_text}, or {days} day(s)" — the two ways out the
  engine already offers as intents (`pay_fine`, `serve`).
- **The chip** (`header`): the worst band across jurisdictions (the highest
  index) and the clarity word — "sought · a description" — as a button
  whose `aria-label` is the full sentence. It focuses the poster's heading
  (desktop) or switches to the Sheet tab (narrow). It is hidden while every
  band is the scale's first word (or out of scale) and clarity is its
  first word — for HUE & CRY, every jurisdiction "unknown" and clarity
  "nothing": nobody is looking for anyone.

**Accessibility.** `<section aria-labelledby>`; the chip is a real button;
nothing is live (the narrator's `law_block` already speaks a change).

**Tests.** Python: `law` carries `scales` equal to the spec's lists; absent
when undeclared (existing test kept); `tests/test_law_narration.py`'s exact
`payload["wanted"]` assertions untouched (the new key is a sibling). vitest
(`ui/tests/wanted-poster.test.jsx`): renders nothing without `law`; renders
every jurisdiction's word; lights the right number of marks; the sketch's

first); an out-of-scale or `""` band lights zero marks; no digit appears in

`src/core/panels/` (Review 25).

- **Who.** `world_sim.merge_npcs_at_location(state, state.location_id)` —
  the same call `present_npc_ids` and the turn schema use

- **No id leaves the server** (Review 10). HUE & CRY's NPC ids ARE names
  (`npc_ardane`, `npc_dock_mag`), and a shipped portrait URL is a manifest

  row carries `key`, an opaque per-response index (`"p0"`, `"p1"`, …) used
  only as a React key.

  ledger says they have met (`relation.met`), else `""` with `known:
  false` — exactly the codex's rule for both (`default_api.py:371-372`
  and `:402`, `"portrait": shipped_art_url(npc_id, "portrait") if met else
  ""`). The strip shows a stranger as a silhouette and a role.
- **Role and activity, gated.** `role_label` (the role humanised as the

  gate (`engine/lore/interceptors.py`,
  `AwarenessGateInterceptor().gate(text, state.awareness, state)`): HUE &

## §6 — The connection (carried item b)

Revised for Review 3, 4, 5, 6, 15, 16, 22, 26, 27 and the controller's
ruling: no fallback to `resume` while the old session may still be live;
controls never re-enabled while a turn is in flight or after the server
dropped it; a hosted refusal goes to login exactly once; Socket.IO's
behaviour after a server refusal handled explicitly. §6.3 is the state
machine, every transition numbered; §6.8 has one test per transition.

### 6.1 What the code does today, verified

- `socket.io-client` is **4.8.3** (`ui/node_modules/socket.io-client/package.json`).
  A `disconnect` whose reason is `"io server disconnect"` is not retried
  by the Manager. A CONNECT_ERROR packet — a server-side refusal of the
  Socket.IO `connect` — calls `this.destroy()` before emitting
  `connect_error` (`ui/node_modules/socket.io-client/build/esm/socket.js:502-507`),
  so a refused socket is NOT retried either. `socket.active` (a getter,
  `socket.js:172`) is true exactly when Socket.IO will retry by itself.
- A transport failure arrives as a `TransportError` whose `type` is
  `"TransportError"` (`engine.io-client/build/esm/transport.js:5-10`). A
  hosted refusal raises `ConnectionRefusedError(text)` with one argument
  (`engine/hosting/sockets.py:82,148`), so the packet is `{"message":
  text}`, `err.data` is `undefined`, and `err.type` is unset. **The
  discriminator is `err.type !== "TransportError"`**, not `err.data`
  (Review 6; the first draft's Risk 7 is dropped).
- A guarded event from a dead login is answered `emit("error", {"error":
  "login required"})` and then `disconnect()` (`sockets.py:377-379`), so the
  client sees an `error` event, then `"io server disconnect"`.
- A rate-limited `resume` or `player_choice` is answered `turn_error`
  (`sockets.py:309-319`), not `resume_failed` (Review 16).
- `join_session` emits `error {"message": "session not found"}` verbatim
  when the session is not live, in local and hosted mode alike — the
  handler raises nothing, so hosted mode's generic-error wrapper never
  rewrites it (`default_scene.py:544-546`; pinned by
  `tests/fixtures/local_mode/*/join_unknown.json`). `join_session` is not
  an action event (`sockets.py:97`, `ACTION_EVENTS = {player_choice,
  resume}`): it spends no rate budget.
- `run_guarded` holds `session.lock` for the whole turn, INCLUDING a hosted
  turn's wait for a narration ticket (`default_scene.py:280-320`); a turn
  cancelled because its socket left releases the lock having changed
  nothing (`PLAYER_GONE`), and its `turn_error` goes to the departed
  socket's sid, i.e. nowhere.
- The front door's 503 body is `{"error": "story unavailable"}`
  (`engine/hosting/frontdoor/proxy.py:145`) — not "restarting" (Review 15).

   (`default_scene.py:547-555`) adds `"turn_running":
   session.lock.locked()` to its `game_started` payload. It is the only

2. **`session_ended`** (§6.5).

### 6.3 The state machine

The store's `link` holds one state. `connected` stays as a derived
boolean (`link` is not `connecting`/`retrying`/`offline`/`signed_out`/
`auth_stuck`) because `Menu` and existing tests read it. **Controls are
live only in `live` with `busy` false**: every chip, approach button, the
compose box and Send are `aria-disabled` otherwise, and `send` returns
early unless `link === "live" && !busy` (F5). Every client emit made by
this machine (`join_session`, `resume`) is guarded by `socket.connected`,
so Socket.IO never buffers one for a later connect (Review 3).

Refs, not closures (Review 26): `connect()`'s handlers are registered
once (`App.jsx:98-110`, `useEffect([])`), so they read `sessionRef`,
`saveRef`, `linkRef`, `busyAtDropRef` and `outgoingRef` (`useRef`s kept
current by an effect), never `state.*`.

**States**

| State | Meaning | Banner (`role="status"` unless noted) |
|---|---|---|
| `connecting` | the page's first connect | none |
| `live` | joined (or no run) and idle or mid-turn on this socket | none; one "Reconnected." after a recovery |
| `rejoining` | socket up; `join_session` sent, no answer yet | "Reconnected — picking up your run…" |
| `awaiting` | rejoined; the server says a turn is still running | "Your move is still being played…" |
| `resuming` | `resume` sent (first connect, or the join's exact miss) | "Opening your run…" |
| `resume_refused` | the resume was refused (`turn_error`) | its message + **Resume** |
| `refused` | hosted: the server refused this socket's `connect` (the connection cap), login still good | the refusal in the server's words + **Try now**, countdown `aria-hidden` |
| `retrying` | socket down, retry scheduled | "Connection lost." + **Try now**, countdown in an `aria-hidden` span (Review 22) |
| `offline` | ≥5 failed attempts, still retrying | "The server is not answering." (or a 503's `error` words) + **Try now** |
| `signed_out` | login ended; navigating once | "Your login has ended. Taking you to sign in…" (`role="alert"`) |
| `auth_stuck` | the bounce guard tripped | "We could not confirm your login." + **Sign in again** link to `/` (`role="alert"`) |
| `elsewhere` | hosted: this run opened elsewhere | "This run is open in another window." + **Play here** |
| `ended` | hosted: ended by the operator or put away idle | "This session was ended. Your run is saved." + **Resume** |

**Events.** S1 socket `connect`; S2 `disconnect(reason)`; S3
`connect_error(err)`; S4 Manager `reconnect_attempt(n)`; P probe answer

**Never resume while the session may be live (B3).** Only transition 18
resumes on a rejoin, and only on the join's own, exact miss. The join
timer (21) re-joins — `join_session` is idempotent (`join_room` plus a
snapshot) — and never resumes; a slow worker costs a longer banner, not a
rebuilt session. Any other `error` (20) is ignored, and `"login required"`
(19) goes to the probe. So no path rebuilds a live session: local mode's
finding 7 is never created, and hosted mode's `_take_owned` refusal of a
build while a turn runs (`store.py:546-552`) is never provoked.

**Never re-enable over a running or dropped turn (M4).**
- A turn still running on the server: transition 17 keeps `busy` and the
  controls off until that turn's `turn_update`/`turn_error` reaches the
  rejoined room (22, 23), with a re-join every 15 s (24) in case its
  answer went to the departed socket. *Not guaranteed (T3 review, finding
  3):* the server emits `turn_update` under the turn lock but releases the
  lock only after `dice_result`, `portrait_ready`, the admission release
  and the turn report, so a join in that window gets the NEW `opening`
  with `turn_running: true` and the `turn_update` has already gone (before
  `join_room`); an HTTP `/api/game/turn` emits nothing to the room at all.
  Transition 24's re-join is what ends `awaiting` then: T11 must not
  shorten or remove the AT poll.
- A turn the server DROPPED (a hosted wait cancelled when the socket went:
  lock released, nothing changed, its `turn_error` sent nowhere): the

**Hosted refusals go to login exactly once.** Transitions 9/10 (and 38 on a first connect) and the

### 6.4 The auth probe

Run at most once every 10 s per tab while not `live`, and at once on
transition 19: `fetch("/api/games/active", {cache: "no-store"})` — gated
like every non-OPEN route (`frontdoor/gate.py:28-38`), and much cheaper
than `/api/games`, which builds the whole catalogue
(`engine/games/api.py:56-65`; Review 15). Answers as in transitions 9–12 and, from `refused`, 38–39. A first connect that fails probes at once (36, 37), so a page loaded with a dead login or over the connection cap never sits silent (Re-review R1).

**Decision: go to `/`, never to `/login`.** The front door's `GET /`
routes a visitor to login, to the account page for an admin-generated
password, or to the story picker (gate rule 4, `frontdoor/gate.py:36-38`),
so the client hardcodes no hosted path, and local mode, which never
answers 401, never navigates.

**The bounce guard.** Before navigating, the client appends `Date.now()`
to `sessionStorage["clockwork_auth_bounce"]` (try/catch, as every storage
access in `socket.js:50-73`). With two bounces already in the last 60 s it
does not navigate (transition 10). Reaching `live` clears the list. So a
door that admits the page and refuses its socket costs at most two
reloads, then a sentence and a link.

### 6.5 `session_ended` (F6)

**Server.** `SessionStore._release(session_id)` passes a reason to the
hook: `on_release(session_id, reason)`, reason `"elsewhere"` (the
one-per-account release, `store.py:555-562`), `"ended"` (an admin's end,
`store.py:764-765`, and `delete`), `"idle"` (the sweep, `store.py:912-918`).
Hosted mode's hook (`engine/hosting/__init__.py:197-200`) emits
`session_ended {"reason": reason, "session_id": session_id}` to the run's
room, then closes it (Review 5: the id lets a tab ignore an event about a
run it has already left). Local mode sets no hook: nothing is emitted and
no local fixture moves. Every test that assigns `on_release` a
one-argument callable is updated in the same task.

**Why the id matters.** In hosted mode `/api/game/new` and
`/api/saves/<id>/load` build with `one_per_owner`, releasing the account's
previous run (`store.py:546-562`) while the tab that pressed Begin is still
in that run's room. With transition 31 the tab has already dropped the old
id before its POST, so transition 30 ignores the event, and 32 sets `live`
when its own new run's `game_started` arrives (`begin` also dispatches no
`RESET` today, `App.jsx:162-179`, which is why the id, not the screen,
decides).

**Contract test.** `_server_events` (`tests/test_ui_contract.py:215-229`)
is extended to scan `engine/hosting/` (Review 8); without that the new
`INBOUND` entry fails `test_client_does_not_listen_for_events_nobody_sends`.

**Not covered by this event:** a story stopped or restarted by the
operator. A drained worker emits nothing; its players reach transitions 4
and 11 (the front door's 503 `"story unavailable"`) and rejoin or resume
when it is back. GOVERNANCE's row is split accordingly (§13, Review 28).

**Decision: no automatic resume after `session_ended`** (transition 29).
The release is the server keeping one live run per account; an automatic
resume would release the other tab, whose automatic resume would release
this one.

### 10.2 What replaces each warning

**Decision: a hard error at config load, naming the file, the old key and
the new one** — `LegacyConfigError(ConfigError)`, raised from the layer
loop in `get_config` for any OPERATOR layer (`config/local.yaml`,
`config/<CLOCKWORK_ENV>.yaml`, each `CLOCKWORK_CONFIG` file, hosted mode's
admin layer) that holds:

| Key | Message (one line each) |
|---|---|
| `lmstudio:` | `{file}: the "lmstudio:" block was renamed "llm:" in v0.19.0 and is no longer read (v0.21.0). Rename the block; "ttl_seconds" inside it is now "keep_alive_seconds".` |
| `stack.services.lmstudio` | `{file}: "stack.services.lmstudio" was renamed "stack.services.llm" in v0.19.0 and is no longer read (v0.21.0).` |
| `paths.saves` | `{file}: "paths.saves" is no longer read (v0.21.0). Saves live under storage.root as <root>/saves: set storage.root (or CLOCKWORK_DATA_DIR) to the folder that holds your saves folder, or move the saves there.` |

**Why an error and not a silent ignore, or a longer warning.** Ignoring an
`lmstudio:` block silently would point the game at the shipped default
server and model — a different narrator, or none — with nothing saying why;
ignoring `paths.saves` would make every save in the old folder vanish from
the menu. Either is a worse failure than refusing to start with the exact
fix. The warning has run for two releases (v0.19.0, v0.20.0), the
CHANGELOG has announced the removal twice, and the config already fails
closed on an operator's mistake: a `CLOCKWORK_CONFIG` file that is missing
raises (`engine/config.py`, the layer loop near `:1156`). A story
manifest's `paths.saves` is a different thing (story data, already ignored
with an advisory since v0.20.0) and keeps its advisory.

**Where the error surfaces.** `launcher.py` and `scripts/start.ps1` /
`start.sh` print the message and exit 2 (a configuration error, distinct
from `--check`'s 1). `scripts/doctor.py` loads the layers raw, as it
already does for its own rows, and reports each as a `Config` **FAIL** row
with the same text instead of raising, so the doctor still runs and lists
everything else. The hosted supervisor's startup check reports it like its
other startup refusals (`engine/hosting/supervisor/__main__.py`, the step
list). The Settings route cannot be reached with such a layer (the process
does not start). **No running path writes such a layer** (Review 20): the
Settings save writes only the panel's own `llm.*`/`world.*` keys, and the
admin layer refuses keys outside its allowlist (`engine/config.py:1013-1020`);
an operator who hand-edits a refused key into a layer of a RUNNING process
meets the error at the next config reset, from whichever caller resets it,
which is the same as a restart.
