## Important

**I1. There is no "dispatch wrapper", and the store cannot see what the RR sounds need (§6.3, §9.7).**
- App passes the raw `useReducer` `dispatch` to `connect`, `createLink`, the phone sender and dozens of
  components (`App.jsx` lines 86-163).
- A wrapper that plays sounds must:
  - wrap that dispatch once, before it is handed out;
  - get `next` by running the pure composed reducer over a shadow `prevRef`, not by reading React state,
    which lags and batches;
  - never play from inside the reducer.
- The spec should name this mechanism and test it: two actions dispatched in one tick each yield their own
  events.
- Separately, the RR slice deliberately does NOT hold the open thread. `state.js`'s header says
  "Navigation (which app, which thread) ... live in `PlayScreen`'s own React state". So `soundFor` cannot
  tell `phone.message_in` from `phone.notify`, and cannot see "the open thread's typing dots". The spec must
  assign these to direct calls in `PlayScreen` or `Thread` / `TypingDots`. Alternatively, `PlayScreen` could
  pass the open thread id into `playSound`'s choice.

**I2. Sounds must not fire when a run is hydrated, and pushes must be de-duplicated.**
- Every diff-based event treats the opening as a change: `game.ending` (sticky `ending`), `panel.wanted`
  (0 to N), `encounter.start`, `clockwork.phase` (dormant to the save's phase), `garden.omen` and
  `neon.watched`. Each would fire on `game_started`, `game_resumed`, a rejoin and `RESET`.
- The fix: fire them only on a `turn_update` (or a `phone_message` / `media_ready`) whose `prev` was already
  a live run. Test it with a resume fixture.
- The RR reducer is idempotent by design ("a push applied twice ... leaves the phone exactly as one
  in-order delivery"), but sound is not. `phone.notify`, `phone.ring` and `phone.message_in` must be keyed
  by message id, with a bounded seen-set, so a duplicate push or a `turn_update` re-carrying the message is
  heard once.
- The spec must also say where `phone.ring` fires. It should be the push carrying the voice or video
  message, not its later `media_ready`. Otherwise one note rings twice.

**I3. RR event overlaps are unresolved (§9.7).**
- With the phone down, a push is both "a message lands anywhere else" (`phone.notify`, essential) and a
  buzz. Rule it: phone down means `phone.buzz` only. The buzz count comes from `world.buzz` in `turn_update`
  (`engine/social/world.py::buzz`) and is not updated by pushes, so say which of the two drives the buzz
  sound between turns.
- Sending a message fires `choice.send` (rebound to `phone.whoosh`), `phone.send` (also `phone.whoosh`) and
  the delegated `ui.press` on the send button. That is three sounds for one press, and per-sound throttling
  only hides one of them. Pick one owner and mark the button `data-sound`.
- The same layering, `ui.press` followed by a store event, applies to the pause menu's "Write" (`game.save`)
  and to any button with a semantic event. §6.3 should state the rule: a control whose action has its own
  event carries `data-sound="none"` or names that event.

**I4. Case-sensitive file names, rule 11 (§4.4, §8.2, §10).**
- The Kenney names are camelCase (`metalLatch.ogg`, `handleCoins.ogg`, `doorOpen_1.ogg`).
- `is_portable_name` checks only device names and trailing dots or spaces, so it never "requires"
  lower-casing.
- A YAML row naming `metallatch.ogg` passes the "file exists" check on this Windows checkout and 404s on
  Linux, Docker and CI.
- Fix: lower-case every imported basename at import, recording `member` with its original case in
  PROVENANCE. Make the §4.4 existence check exact-case: the name must appear in its directory's listing, not
  merely satisfy `Path.exists()`. §10's "file names are lower-case-safe" is currently untrue.

**I5. Ogg on WebKit matters for hosted READ RECEIPTS (§8.3, R4).**
- Locally the owner plays in Chrome or Edge on Windows. Safari exists only on macOS, an untested platform, so
  for local play it is negligible.
- In hosted mode, though, READ RECEIPTS is a phone story. On iOS every browser is WebKit, and older WebKit
  cannot decode an `.ogg` file. The spec's "Safari before 17.4" boundary is asserted, not verified; T7 should
  confirm it and state it as measured.
- Proposed fallback, which stays inside the no-transcoding provenance rule:
  1. Require a `fallback` synth on EVERY file sound. It is a few lines of YAML each, and then no browser
     ever loses a cue.
  2. Probe `canPlayType('audio/ogg; codecs="vorbis"')` once, and go straight to the fallbacks, without
     fetching, when it answers "".
- The audition page should then show "fallback" against each file row on such a browser.
- Shipping AAC twins is not worth it: it means transcoding, twice the bytes and a derived-file provenance
  row. Narrow the GOVERNANCE row to "file sounds play as their synth fallback on browsers without Ogg
  Vorbis".

**I6. The lift's minutes would be pinned as they are, which looks like a bug (§12.2).**
- `world.go` adds `life.extra_minutes` to EVERY move (`engine/social/world.py:571`). That includes
  lounge to kitchen inside the flat, and scene closers through `scene._go`.
- The v0.23.0 plan (T25) intended the stairs edge only: "adds 5 minutes to the stairs edge".
- `test_the_lift_adds_its_minutes_to_go` must not freeze a 6-minute walk to your own kitchen. T2 should
  either apply the minutes only when leaving or entering the building (the ring-0 flat to anywhere else), or
  record the current behaviour as an owner-visible deferred row.
- Also, §12.2 says "T10 only pins it with a test"; that should read T2.

**I7. `lasts_days` decides whether a life event's news shows at all (§12.2).**
- `life.running` needs `until`, and `player_news` reads only running events. So today `wedding_invite` and
  `promotion`, which both have `news: player_news` and no `lasts_days`, never offer their tell_about topic
  or their news.
- Adding `lasts_days: 5` to `wedding_invite` silently turns its news on for five days. That is a behaviour
  change T11 must measure and the CHANGELOG must say.
- `promotion` stays dead. Extend the new check to cover it: a player row with `news` needs `lasts_days`.
  Then either fix `promotion` or give it a deferred row.

**I8. T14 is under-sized and its range should be explicit (§13, §16).**
- v0.23.0 was squash-merged, so its four commits are one range: `git diff 60215f4..6de3f2b`, from v0.22.0
  to v0.23.3. That is 313 files, +53,285/-6,553 lines, of which 264 files and +36,648 lines are engine, ui,
  games, scripts and tests. On top of that comes `main...release/v0.24.0`.
- One opus reviewer cannot read that with care inside an M. Make T14 an L (31 units).
- Split T14 into area reviewers: engine/social; ui and the client contract; data, docs and tests; and this
  branch's sound work. The controller merges their findings.
- Name both ranges as git commands in the task, so the reviewer diffs the right bases.

## Minor

- **M1, module state (§3).** An `lru_cache` loader is reset through `caches.py`'s `LRU_CACHES` with
  `cache_clear()`, not through `NULLED_ATTRIBUTES`. The "read once into a local" rule applies only to the
  latter. A `manifest` dict is unhashable, so key the cache on `(slug, path, mtime)` as the other per-story
  loaders do. The verdict row and the `WARMERS` row stand.
- **M2, S13 (§10).** `app_shape.json` records `url_map`, the hooks, `socketio` and `run_kwargs`, but no
  blueprint list. So S13 is exactly three `url_map` rows (with their endpoint names), plus nothing else.
  Assert that no `before_request` or `after_request` row moves.
- **M3, S12 (§10).** The recorded `games.json` holds five of the six declaring rows. READ RECEIPTS' row comes
  from S11's `READ_RECEIPTS_ROW` constant, which is edited in place by precedent (its comment lists T10, T11,
  T23F and T26). So S12 touches five recorded rows, plus that constant gaining `paths.sounds`. S12 is
  necessary, because the catalogue serialises every path. It is minimal, and dev-story's row does not move.
- **M4, hosted.** Files behind a login should be `Cache-Control: private, max-age=...`, not bare `max-age`.
- **M5, hosted.** `/sound/<slug>/...` should 404 for a slug outside `hosting.stories`, matching the catalog
  route.
- **M6, MIME type.** Pass `mimetype="audio/ogg"` explicitly. `send_generated` guesses the type, and Windows'
  registry can map `.ogg` differently.
- **M7, autoplay (§6.2).** "One capturing listener, removed once it fires" contradicts "a context the
  browser suspends later is resumed on the next gesture". Keep a cheap listener that only calls `resume()`
  when `state !== "running"`. On iOS the unlock must happen in `touchend` or `click`; `pointerdown` from a
  touch does not grant activation there. Keep `touchend` and test it.
- **M8, unused imports (§8.1).** `dice-shake-1`, `impactGlass_light_000`, `glass_002` and `drop_002` are
  imported but bound nowhere in §9. Either bind them or drop them; the provenance test would carry dead
  rows.
- **M9, the per-file cap.** Say what happens when a file is over 48 KiB. Without transcoding it cannot be
  shrunk, so T7 takes another member of the same pack and records it, as R3 already does for a missing name.
- **M10, `alert.notice` (§5.1).** "Core's notice line" names nothing in `store.js`. The only banner is the
  link banner, which `link.lost` already covers. Name the source or drop the event.
- **M11, borrowed plugins.** Two gaps:
  - `test_sound_events.py` should map plugin to story through each manifest's `ui.plugin`, because a plugin
    is not a story.
  - "In vitest, `playSound` of an undeclared event throws" will fail any test that renders a borrowed
    plugin. Let the test say which catalogue it runs under.
- **M12, §12.1 wording.**
  - The chance `prior_bias` is applied in `_open`, the `social_scene` handler, not in `open_scene`.
  - `close()` routes unknown names to its back_to/go_somewhere branch, so `see_them_out` needs its own
    branch.
  - The morning's `_end` still writes a history row ("The morning after, at yours: ..."). Say whether that
    is wanted.
- **M13, T11's harness.** It reaches the decks only if its policies stand in `apt_hall`, `bldg_lift` and
  `apt_lounge`. Today they `go` straight to venues, so "walk past the four new decks" needs an explicit room
  walk.
- **M14, rule 9.** Add "no sound in the studio or the admin panel" to §15 as a row naming a file. It is a
  non-goal, and the owner asked for "the engine itself".
- **M15, T1's size.** T1 has grown past the plan's S: a new `check_data` block, the closers, the
  night's-tail rule in `_end`, and the client heading. M is more honest. With I8 the total becomes 32 units.
- **M16, Settings test.** Renaming "Mute narration audio" to "Mute all sound" may break existing UI tests
  that query that label. T6 should grep for it.

## Re-review of the revised spec (scoped)

**Verdict: Approved.** I1-I8 are each addressed in the text (not only in the Review rulings table): direct calls
with keys, `markSeen` and sent-turn gating (§6.3, §9.7); one sound per action (rule 3, §9.7); lower-case import and

Two clarifications for the build (not blockers; fix in the spec or at the task):
1. `scene.open` (§9.7) is gated on "a turn or phone action this page sent", but `turnSent()` is called only by
   core's choose, custom and begin handlers and `turnSettled()` by App's busy-effect. READ RECEIPTS' phone actions
   have no stated route to either. T9 must route the phone sender through `turnSent`/`turnSettled`, or key
   `scene.open` by scene id with `markSeen` on hydration instead.
2. The lift fix says "in the flat-and-building set (`places.is_flat`, the `home` and `building` tags; ring 0)".
   If the cast's homes carry the `home` tag, `back_to_theirs` would still pay, contradicting the test. Say the set
   is the player's flat and building only. Also, T12's "a refresh logs only `seen` drops" is true only when a
   later call reaches a key already in the seen-set; `markSeen` itself logs nothing.
